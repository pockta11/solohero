MVP 개발 계획서 (SoloHero)

0) 문서 목적과 원칙
목적: “기본 기능만으로도 플레이 루프가 완결되는” 출시 전 단계의 MVP를 만들기 위한 개발/QA/릴리즈 계획을 정확히 분류해 문서화한다.

원칙
- 루프 우선: 새 기능 추가보다 “루프가 끊기지 않음(데이터/플로우/안정성)”을 최우선.
- 스키마 고정: MVP 기간에는 PlayerData/저장 구조의 큰 변경을 금지(변경 시 마이그레이션 문서 포함).
- 저장 안전성 우선: 네트워크 불안정/강제종료에도 유실 없이 복구가 되어야 한다.
- 범위 통제: MVP는 “가능한 최소 기능” + “사용자가 체감하는 완성도”만 포함.

1) MVP 정의
1.1 MVP 한 줄 정의
오프라인으로 골드를 얻고(수령), 전투로 스테이지가 진행되며, 골드로 장비를 뽑아 장착/인벤/강화로 성장하고, 재실행해도 모든 상태가 유지되는 게임.

1.2 핵심 플레이 루프(필수)
앱 실행 → 로그인/로드 → 오프라인 보상 팝업(조건부) → 전투/스테이지 진행 → 보상 골드 획득 → (가챠/인벤/강화)로 성장 → 자동 저장 → 앱 종료/재실행 → 동일 상태 복원

1.3 MVP “완료(Definition of Done)”
아래가 모두 충족되면 MVP 완료.

기능 DoD
- 신규 유저: 첫 실행부터 게임 진입까지 막힘 없음
- 기존 유저: 재실행 시 동일 상태(골드/강화/장비/스테이지)가 복원됨
- 오프라인 보상: 경과 시간 계산, 상한 적용, 수령 후 골드 반영/저장 완료
- 장비: 뽑기→자동 장착 또는 인벤 적재→스탯 반영→저장 완료
- 강화: 비용 차감→스탯 반영→저장 완료
- 스테이지: 킬 목표/클리어/보상/자동 다음 진행이 연속 동작

품질 DoD
- 강제 종료 후에도 마지막 저장 지점까지 복구 가능
- 30분 연속 플레이/방치에서 진행 멈춤, 메모리 폭증, 치명적 오류 없음(최소 기준)

릴리즈 DoD
- Android AAB 1회 이상 빌드/설치/실행 성공(개발 기기 기준)

2) 범위 명세(Scope)
2.1 MVP 포함(In Scope)

인증/진입
- 익명 로그인
- 첫 실행(신규 데이터 생성) / 재실행(기존 데이터 로드)
- 로드 중 UI(간단한 로딩/상태 메시지)

데이터/저장
- 원격 저장(Firebase RTDB) + 로컬 백업(PlayerPrefs 등)
- 자동 저장 트리거(아래 4.4에 정의)
- 최소한의 데이터 무결성(중복 저장/경합 방지)

오프라인 보상
- UTC 기반 경과 시간 계산
- 최대 6시간 상한
- 팝업 표시 및 수령(일반 수령)

전투/스테이지
- 자동 전투(기본 공격/간단 스킬이 이미 있다면 포함)
- 스테이지 킬 목표, 클리어, 골드 보상
- 자동으로 다음 스테이지 진행

장비/인벤
- 장비 뽑기 1회(가능하면 10회는 MVP+)
- 자동 장착/인벤 처리 규칙
- 인벤 UI(목록/선택/장착 변경)
- 장착 상태 및 합산 스탯 UI 요약(최소)

강화(Upgrade)
- HP/ATK/DEF/SPD 강화
- 비용 공식/최대 레벨
- UI 및 즉시 반영

UI/네비게이션
- 하단 탭/패널 구조(열면 닫힘 규칙)
- HUD: 골드, 스테이지 진행(킬/목표), HP/SP 등 최소 표시

2.2 MVP 제외(Out of Scope, v1.0 이후)
- 정복자(오픈맵), 길드, 다수 던전, 쉘터/기지
- 동료 시스템, 스킬 소환풀(별도 가챠), 분리된 다중 소환풀
- 장비 고급화(5라인/소켓/승급/재감정)
- 이벤트/패스/상점 고도화
- 광고 2배 보상(“MVP+”로 분리 권장)

2.3 MVP+ 권장(시간 남으면)
- 오프라인 보상 보상형 광고 2배
- 장비 뽑기 x10
- 간단한 설정 메뉴(사운드/진동/계정/데이터 초기화는 주의)

3) 시스템별 요구사항(정확 분류)
3.1 인증/초기화
입력: 앱 실행, 네트워크 상태
출력: LoginScene → GameScene 안정 전환

필수 요구
- 최초 실행 시 기본 PlayerData 생성 및 저장
- 기존 데이터가 있으면 로드 후 게임 상태 적용
- 네트워크 실패 시 로컬 백업으로 시작 가능(단, 충돌 정책은 4.3)

3.2 저장/로드(핵심)
요구
- “중요 행동 직후 저장”으로 유실 최소화
- 저장 중 중복 호출 방지(큐/플래그)
- 원격 저장 실패 시 로컬 백업 저장은 반드시 성공

완료 기준
- 강제 종료 후 재실행해도 마지막 저장 지점이 합리적으로 복구됨

3.3 오프라인 보상
계산
- lastQuitTimeUtc 기준 경과 계산
- 상한: 21600초(6시간)
- 보상: (reward = seconds \\times rate) (MVP에서는 rate 고정 가능)

플로우
- 로드 완료 후 오프라인 시간이 유효하면 팝업 표시
- 수령 버튼 → 골드 반영 → 저장

완료 기준
- 시간 조작/음수/비정상 값에서 크래시 없이 안전 처리(최소 방어)

3.4 스테이지/전투
스테이지 요구
- 킬 목표 표시
- 적 처치 시 진행도 업데이트
- 클리어 시 보상 지급 + 다음 스테이지 이동

전투 요구
- 자동 전투 ON이 기본이어도 되며, MVP에서는 토글이 필수는 아님(있으면 좋음)

완료 기준
- 30분 방치 시 진행이 멈추지 않고 계속 스테이지가 돈다(최소 기준)

3.5 장비/가챠/인벤
가챠 요구
- 확률/분포(이미 구현된 정규분포 + 천장) 유지
- 결과 아이템 생성 → 장착/인벤 규칙 적용 → 저장

인벤 요구
- 리스트 표시
- 아이템 선택/장착
- 장착 변경 시 즉시 스탯 반영 및 저장

완료 기준
- “뽑기→장착→강해짐 체감”이 전투/스테이지에서 확인됨

3.6 강화(Upgrade)
요구
- 골드 비용 계산 정확
- 최대 레벨 제한
- 강화 성공 시 즉시 스탯 반영 및 저장

완료 기준
- 강화 연타/빠른 입력에도 골드 음수/중복 적용 등의 문제가 없어야 함

3.7 UI/네비게이션
요구
- 하단 탭 또는 버튼으로 패널 전환
- “한 패널 열면 다른 패널 자동 닫힘”
- HUD 최소 정보 표시

완료 기준
- 사용자가 길을 잃지 않고 “전투 ↔ 성장(가챠/인벤/강화)”을 반복 가능

4) 데이터/정책 문서(정확한 규칙)
4.1 PlayerData MVP 필드(예시 수준의 고정 리스트)

경제
- gold

진행
- chapter, stage 또는 내부 스테이지 인덱스
- killCountInStage(필요 시)

강화
- upgradeHpLevel, upgradeAtkLevel, upgradeDefLevel, upgradeSpdLevel

장비
- equippedWeaponId, equippedHelmId, equippedArmorId, equippedBootsId
- inventoryEquipmentIds(CSV/리스트)

오프라인
- lastQuitTimeUtc(Unix seconds)

버전
- dataVersion(스키마 변경 대비)

MVP 기간에는 위 필드 외 확장을 최소화하고, 확장 시 dataVersion 마이그레이션 규칙을 문서로 추가.

4.2 장착/인벤 규칙(명시)

규칙 예시
- 신규 장비 획득 시: 해당 슬롯 장착 장비보다 등급/스탯이 좋으면 자동 장착, 아니면 인벤
- 인벤 상한(MVP에서는 무제한 가능) / 상한이 있다면 초과 처리 규칙 필요

필수
- 규칙이 UI 표시와 일치(“자동 장착됨/인벤으로 들어감” 피드백)

4.3 원격 vs 로컬 충돌 정책(필수)

권장 MVP 정책(단순/안전)
- 원격 로드 성공 시 원격을 우선
- 원격 실패 시 로컬 백업으로 시작
- 원격 복구 시점에 “로컬→원격 덮어쓰기”는 MVP에서는 자동으로 하지 않거나, 매우 보수적으로(유저 선택 없이 덮어쓰기는 위험)

완료 기준
- 어떤 경우에도 데이터가 “초기화”처럼 보이지 않게(최소 방어 UI 포함)

4.4 저장 트리거(정확히 정의)

항상 저장
- OnApplicationPause(true) / OnApplicationQuit

행동 기반 저장
- 스테이지 클리어 직후
- 가챠 결과 확정 직후
- 장착 변경 직후
- 강화 성공 직후
- 오프라인 보상 수령 직후

저장 규칙
- 저장 호출이 연속될 경우 디바운스/큐로 정리(“마지막 상태” 1회 저장)

5) 일정/마일스톤(정밀 분류)
5.1 Milestone A — 기준선 고정(0.5~1일)
- 씬 플로우(로그인→게임) 확정
- PlayerData MVP 스키마 확정 + dataVersion 확정
- 저장 트리거/충돌 정책 확정

완료 조건
- 신규/기존 두 케이스에서 “게임 진입”이 10회 중 10회 성공(개발 환경)

5.2 Milestone B — 데이터 안정화(2~3일)
- 저장 큐/중복 방지
- 원격 실패 시 로컬 백업 동작
- 오프라인 보상 계산/수령/저장 완결

완료 조건
- 강제 종료 후 재실행 20회 시나리오에서 핵심 데이터 유실 0

5.3 Milestone C — 성장 루프 완성(2~4일)
- 스테이지 보상→골드 증가→가챠→장착/인벤→강화→전투 반영
- UI 패널 전환 규칙(열면 닫힘) 일관

완료 조건
- 30분 플레이로 “성장 체감 + 루프 반복”이 가능한 상태

5.4 Milestone D — MVP QA & 릴리즈(2~3일)
- 필수 시나리오 테스트(6장 참고)
- Android AAB 빌드/설치/실행

완료 조건
- QA 필수 10개 시나리오 All Pass + AAB 실행 성공

6) QA 계획(테스트 케이스 문서)
6.1 필수 시나리오(최소 10개)
- S1 신규 진입: 설치→첫 실행→로그인→신규 데이터 생성→게임 진입
- S2 기존 복원: 플레이(가챠/강화/스테이지 진행)→종료→재실행→동일 상태 복원
- S3 오프라인 10분: 종료 10분 후 재실행→팝업→수령→골드 반영/저장
- S4 오프라인 6시간 상한: 종료 후 긴 시간(혹은 테스트 훅)→상한 적용 확인
- S5 네트워크 끊김(시작 시): 네트워크 OFF→실행→로컬 백업으로 진입(또는 안전한 실패 처리)
- S6 네트워크 끊김(저장 중): 저장 시점에 끊김→크래시 없이 로컬 저장 유지
- S7 가챠 연속: 20회 이상 연속 뽑기→인벤/장착/스탯 반영 정상
- S8 장착 변경: 인벤에서 장비 교체→전투 스탯이 즉시 변함→재실행 후 유지
- S9 강화 연타: 강화 10회 연속→골드/레벨/스탯/저장 정상
- S10 30분 방치: 자동 전투/스테이지가 멈추지 않고 진행(에러/폭주/멈춤 없음)

6.2 합격 기준(정량/정성)

치명(Critical) 버그 0
- 데이터 유실/초기화처럼 보임
- 진행 불가(씬 전환 실패, UI 입력 불가)
- 무한 로딩/무한 저장으로 게임 정지

주요(Major) 버그 최소화
- 골드 음수, 장비 중복/소실, 강화 수치 불일치

7) 리스크 관리(정확 분류)
7.1 데이터 리스크
- 경합 저장: 여러 시스템이 동시에 저장 호출 → 데이터 덮어쓰기
  - 대응: 단일 저장 파이프라인(큐/락), 마지막 스냅샷 저장
- 원격/로컬 불일치
  - 대응: 충돌 정책을 MVP에서 단순하게(원격 우선, 실패 시 로컬)

7.2 씬/프리팹/에셋 리스크
- 씬 변경이 잦으면 MVP 안정화가 늦어진다
  - 대응: MVP 기간 동안 씬 구조 변경 금지, 필요한 수정만

7.3 성능 리스크(방치형 핵심)
- 파티클/풀링/스폰 누수로 30분 방치에서 망가질 수 있음
  - 대응: 30분 방치 테스트를 “개발 중간”부터 반복

8) 릴리즈 준비 체크리스트(MVP)

빌드
- AAB 빌드 성공
- 기기 설치/실행 성공

첫 실행 경험
- 로딩/팝업/첫 화면 동선이 막히지 않음

데이터
- 신규/기존 시나리오 Pass

핵심 루프
- 전투/스테이지/보상/가챠/강화/저장/복원 Pass

9) “오늘부터 바로 쓰는” 작업 분해(실행 단위)

저장/로드 안정화
- 저장 트리거 통합(한 곳으로 모으기)
- 저장 중복 방지(저장 중이면 마지막 요청만 유지)
- 원격 실패 시 로컬 저장/로드 동작 확인
