# SoloHero - Game Design Document

**Author:** Tae-jun
**Game Type:** Idle/Incremental (주축) + RPG (병합)
**Target Platform(s):** Android — Google Play, AAB / Portrait 1080×1920

---

## Executive Summary

### Core Concept

세로 화면 픽셀아트 2D 횡스크롤 방치형 RPG. 히어로는 화면 오른쪽으로 자동 전진하며 등장하는 적 웨이브를 스스로 처치하고, 플레이어는 전투를 조작하지 않는다. 플레이어의 행동은 **성장 결정**뿐이다 — 골드를 강화에 넣을지 장비 가챠에 넣을지, 어느 스테이지를 파밍할지, 광고를 볼지.

게임의 심장은 두 가지다. 첫째, 앱을 끈 시간이 골드로 환산되는 **오프라인 축적**(최대 6시간). 둘째, 등급별 확률을 게임 안에서 공시하고 200회에 전설(Legendary)을 보장하는 **투명한 천장 가챠**(D-113: 장비 7등급). 플레이어는 확률표와 `천장까지 N회` 게이지로 다음 Legendary까지의 거리를 항상 본다. 가챠 방식 자체는 장르 표준(등급별 확률표 + N회 천장)을 따른다.

한 판의 리듬은 짧다. 일반 스테이지 1회는 약 25초, 챕터당 10스테이지의 마지막이 보스다. 보스에서 막히면 좌절 대신 **후퇴(Retreat) 파밍 모드**로 전환되어 직전 스테이지를 반복하며 다시 강해진다.

### Target Audience

| 페르소나 | 프로필 | 플레이 동기 | 설계 함의 |
|---|---|---|---|
| **P-A. 출퇴근 방치러** (주 타깃) | 25~40세 모바일 게이머, 하루 3~5회 실행 × 회당 2~5분, 한 손 세로 조작 선호. 버섯커 키우기·세븐나이츠 키우기 경험 | 짧은 틈에 "숫자가 늘어난 것"을 확인하는 만족. 전투 조작은 피로로 인식 | 세로 1손 레이아웃, 앱 켜자마자 3탭 안에 성장 완료, 전투 무조작 |
| **P-B. 확률 분석러** (보조 타깃) | 가챠 확률 구조에 흥미, 기댓값·천장 계산을 즐기고 커뮤니티에 공유 | 확률이 투명하게 공시되고, 천장까지의 거리와 기댓값을 직접 계산할 수 있는 구조 | pity 진행도 게이지 상시 노출, 확률 공시표를 게임 내에서 열람 가능 |
| **P-C. 픽셀아트 취향자** (부수) | 레트로 픽셀 연출·도트 이펙트를 선호 | 비주얼 자체가 체류 이유 | 픽셀 퍼펙트 유지, 히트 플래시·데미지 텍스트 연출 품질 |

**세션 설계**

| 단위 | 플레이어가 하는 일 | 체감 목표 |
|---|---|---|
| **3분** (앱 켜고 끄기 1회) | 오프라인 보상 수령(광고 2배 선택) → 강화 2~4회 → 가챠 1~3회 → 장비 장착 확인 → 종료 | "짧게 들어와도 확실히 세졌다" |
| **15분** (한 자리에서) | 위 + 스테이지 5~10개 진행, 보스 1회 도전, 스킬 레벨업, 막히면 후퇴 파밍 | "벽이 있었는데 넘었다" |
| **하루** (누적 4~5세션) | 챕터 절반~1개 진도, 광고 슬롯 소진, 젬 누적 → 며칠에 1회 10연 가챠 | "하루 치 진도가 눈에 보인다" |

### Unique Selling Points (USPs)

1. **천장까지 몇 번인지 항상 보인다.** 장비 7등급 확률(일반 60 / 고급 28 / 희귀 9 / 영웅 2.5 / 전설 0.45 / 신화 0.045 / 고대 0.005 %, D-113)을 게임 안에서 공시하고, `천장까지 N회` 게이지를 가챠 패널에 상시 노출하며, 200회 천장에서 전설을 보장한다. 소환은 메이플 키우기처럼 단계를 밟는다(D-123): 1단계는 일반만, 단계가 오를 때마다 한 등급씩 열리고 좋은 등급이 더 잘 나온다 — 처음 소환에서 운으로 고대가 나오는 일은 없다. 천장은 전설이 열린 단계부터 센다. 중복은 즉시 골드로 환급되어 뽑기가 헛되지 않는다. 방식은 장르 표준이고, 차별점은 **숨기는 것이 없다**는 점이다.
2. **껐던 시간이 복귀 보너스가 된다.** 최대 6시간까지 골드가 쌓이고, 초당 획득량이 현재 파밍 스테이지에 연동되어 진행할수록 방치 수익도 커진다. 광고 1회로 2배. 주 수입은 온라인 파밍이고 오프라인은 보조이므로, 방치만으로 진행이 끝나버리지 않는다.
3. **세로 한 손 + 25초 스테이지.** 경쟁작 다수가 가로 기준인 반면 전 화면을 한 손 세로로 설계한다. 스테이지 1회 25초, 챕터 10스테이지로 "진도"를 초 단위로 체감시킨다.
4. **막혀도 루프가 끊기지 않는다.** 보스 실패가 게임 오버가 아니라 후퇴 파밍 모드 진입이다. 플레이어는 항상 다음에 할 일이 있다.

## Goals and Context

### Project Goals

| # | 목표 | 정량 기준 |
|---|---|---|
| G-1 | 1인 개발로 Google Play 출시 가능한 완성도의 v1.0을 낸다 | AAB 빌드·설치·실행 성공, Critical 버그 0 |
| G-2 | 방치형 핵심 루프가 30분 연속 플레이에서 성립한다 | 진행 멈춤·메모리 폭증·치명 오류 없음, 30분 내 성장 체감 |
| G-3 | 저장 신뢰성을 확보한다 | 강제 종료 20회 시나리오에서 핵심 데이터 유실 0 |
| G-4 | 가챠 확률을 검증 가능한 형태로 공시한다 | 게임 내 공시표 = 실제 확률표. 검증기 실측(10만 회) 오차 1%p 이내 |
| G-5 | MVP 콘텐츠 분량을 확보한다 | 챕터 5개 × 10스테이지 = 50스테이지, 적 8종·보스 3종·장비 16종·스킬 3종 |

### Background and Rationale

SoloHero는 쿼터뷰 **3D** 방치형 액션 RPG로 개발되어 전투·스테이지·가챠·인벤토리·Firebase 저장·오프라인 보상까지 동작하는 상태에 도달했다(약 5,900줄 / 49개 스크립트). 3D 모델·Animator 교체 단계에서 1인 개발로 감당 가능한 아트 파이프라인이 아니라는 판단이 서면서, **2D 세로 픽셀아트로 전면 피벗**하기로 결정했다.

피벗의 근거는 세 가지다.

1. **아트 비용.** 3D 모델·리깅·애니메이션 교체는 1인 개발의 실질 병목이었다. 픽셀아트 무료 에셋은 확보·교체·플레이스홀더 대체가 훨씬 싸다.
2. **장르 정합성.** 조작을 최소화하는 방치형에서 3D 쿼터뷰 이동·NavMesh 추적은 비용만 크고 체감 가치가 낮았다. 2D 횡스크롤 자동 전진은 "진도"를 가장 값싸게 보여주는 표현이다.
3. **차별화.** 레퍼런스 게임 Soul Strike를 포함한 경쟁작 다수가 가로 화면이다. 세로 한 손 플레이는 출퇴근 세션과 맞물리는 실질 차별점이다.

**계승과 폐기가 명확히 갈린다.** 천장 가챠의 구조(100회 보장·4슬롯×4등급·자동 장착), 오프라인 보상, 광고 2배, 저장 아키텍처(원격 + 로컬 백업 + 디바운스), 빌드 파이프라인, Firebase/AdMob 인프라는 계승한다. 3D 전투(NavMesh·구체 판정), 가로 레이아웃 UI 구현, 3D 에셋, 선형 강화·스테이지 공식, 그리고 **정규분포 기반 가챠 등급 결정**(아키텍처 단계에서 장르 표준 확률표로 대체)은 폐기한다.

**레퍼런스에서 가져올 것 / 안 가져올 것**

| 요소 | Soul Strike | SoloHero 판단 |
|---|---|---|
| 하단 탭 → 패널 슬라이드업, 하나만 열림 | 하단 5탭, 화면 ~50% 슬라이드 | **가져온다.** 구조만 계승, 세로 그리드로 재구성 |
| Chapter-Stage 진행 포맷 | 1-1 ~ 6-100 | **가져온다.** 단 챕터당 10스테이지로 축소 |
| 천장 가챠 | N회 후 최상위 보장 | **가져온다.** 200회 전설 보장 (D-113, 이전 100회) |
| 오프라인 보상 + 광고 2배 | 동일 | **가져온다.** MVP In |
| 가로 화면이 차별점 | "lean into it fully" | **안 가져온다.** 세로 확정 |
| 능동 스킬로 손맛 | "pure idle is boring" | **부분 수용.** 스킬 자동 발동을 기본으로 두고, 탭으로 즉시 발동만 허용 |
| 소환풀 5종 분리 (Job/Skill/Companion/Artifact/Pet) | 다중 풀 | **안 가져온다.** v1.1+ 후보 |
| 성장 4계층 (Training/Traits/Awakening/Constellation) | 다층 메타 | **안 가져온다.** 후반 성장은 소환 단계·승급·펫·업적으로 (프레스티지는 D-126에서 제외) |
| 코스메틱 ~999종, 배틀패스 | 수익화 축 | **안 가져온다.** v1.1+ |
| 최적화가 불만 1위였다는 교훈 | 드로우콜·파티클 통제 | **가져온다.** 성능 예산을 목표치로 명시 |

## Core Gameplay

### Game Pillars

| # | 필러 | 정의 | 이 필러가 기각하는 것 |
|---|---|---|---|
| **P1** | **손을 떼도 성장한다** (Zero-Input Progress) | 전투는 플레이어 입력 없이 성립한다. 앱을 꺼도 골드가 쌓인다. 플레이어의 입력은 전투가 아니라 성장 결정에만 쓰인다 | 이동 조작, 타이밍 회피, 수동 기본 공격, 클리커 탭 |
| **P2** | **25초 스테이지, 한 손 세로** (One-Thumb Portrait Rhythm) | 일반 스테이지 1회 약 25초. 모든 화면은 세로 1080×1920에서 한 손 엄지 도달 범위 안에 있다 | 가로 전용 HUD, 양손 조작, 긴 스테이지, 화면 상단 주요 버튼 |
| **P3** | **확률이 보이는 가챠** (Transparent Gacha) | 등급별 확률과 천장 규칙을 게임 안에서 공시하고, 천장까지 남은 횟수를 항상 보여준다. 플레이어가 기댓값을 계산할 수 있어야 한다 | 숨겨진 확률, 확률 미공시, 천장 진행도 비노출, 공시표와 다른 실제 확률 |
| **P4** | **벽과 돌파의 리듬** (Wall and Break) | 난이도 성장률이 수익 성장률보다 높아 의도적 정체 구간이 생긴다. 정체는 강화·장비·스킬 중 하나를 골라 돌파한다. 막힘은 실패가 아니라 파밍 전환이다 | 무저항 우상향 곡선, 보스 실패 시 게임 오버, 재화 단일 소비처 |

**추적 체인.** Core Concept → 4개 필러 → 핵심 루프 → 각 시스템 → 개발 에픽. 어떤 필러에도 봉사하지 않는 메카닉은 범위 초과로 취급한다.

**필러를 4개로 둔 이유.** 3개가 권장 상한이지만, P2(세로 한 손 리듬)를 빼면 세로 화면·25초 스테이지·엄지 도달 범위라는 형식 제약이 어떤 필러에도 묶이지 않고, P4(벽과 돌파)를 빼면 난이도 곡선과 골드 소비처 경쟁이 근거를 잃는다. 넷 다 실제로 기각 결정을 내리는 데 쓰이므로 슬로건이 아니다.

### Core Gameplay Loop

```mermaid
flowchart TD
    A[앱 실행] --> B{오프라인 경과 시간 > 60초?}
    B -- 예 --> C[오프라인 보상 팝업<br/>일반 수령 / 광고 2배 수령]
    B -- 아니오 --> D
    C --> D[자동 전투 진입<br/>현재 파밍 스테이지]
    D --> E[적 웨이브 자동 처치<br/>스킬 자동 발동]
    E --> F[킬 목표 8마리 달성]
    F --> G[스테이지 클리어<br/>골드 + EXP 획득]
    G --> H{다음이 보스 스테이지?}
    H -- 아니오 --> D
    H -- 예 --> I[보스 전투<br/>30초 제한]
    I -- 성공 --> J[챕터 클리어<br/>골드 + 젬 + 다음 챕터 해금]
    I -- 실패 --> K[후퇴 파밍 모드<br/>직전 스테이지 반복]
    J --> D
    K --> D
    G --> L[성장 결정]
    L --> M[강화: 골드 → HP/ATK/DEF/공격속도]
    L --> N[가챠: 골드 → 장비 + pity 누적]
    L --> O[스킬 레벨업: 골드 → 스킬 계수]
    M --> P[스탯 즉시 반영 → 전투 DPS 상승]
    N --> P
    O --> P
    P --> D
    D --> Q[앱 종료 / 백그라운드]
    Q --> R[종료 시각 저장 → 오프라인 누적 시작]
    R --> A
```

**각 단계의 체감 목표**

| 단계 | 체감 목표 | 실패 신호 |
|---|---|---|
| 오프라인 보상 수령 | "안 하고 있었는데도 벌어놨다" | 보상이 강화 1회 비용도 안 됨 |
| 자동 전투 | "내가 안 눌러도 잘 싸운다" | 히어로가 멈춰 보임, 적이 안 죽음 |
| 스테이지 클리어 | "진도가 초 단위로 나간다" | 1스테이지가 1분을 넘김 |
| 성장 결정 | "무엇에 쓸지 고민된다" | 소비처가 하나뿐이라 고민이 없음 |
| 스탯 반영 | "쓴 만큼 바로 세졌다" | 강화 후 전투 시간이 그대로 |
| 보스 | "이번엔 넘을 것 같다" | 왜 졌는지 모름 |
| 후퇴 파밍 | "다시 도전할 수 있다" | 막힌 뒤 할 일이 없음 |

### Win/Loss Conditions

**승리 조건 없음.** 방치형 무한 진행 구조로, 최종 엔딩이 없다. v1.0의 콘텐츠 종료선은 **챕터 5 보스(스테이지 5-10) 격파**이며, 그 이후는 챕터 6+가 테마를 순환 재사용하며 공식으로 무한 확장된다.

**패배 조건은 전투 단위로만 존재한다.**

| 상황 | 판정 | 결과 |
|---|---|---|
| 일반 스테이지에서 히어로 HP 0 | 스테이지 실패 | 3초 후 같은 스테이지 처음부터 자동 재시작. HP 전량 회복. 페널티 없음(획득 골드·EXP는 유지) |
| 보스 스테이지에서 히어로 HP 0 | 보스 실패 | 실패 팝업 → 재도전 / 후퇴 파밍 선택 |
| 보스 제한 시간 30초 초과 | 보스 실패(시간) | 동일. 팝업에 "남은 보스 HP %" 표시로 얼마나 부족했는지 보여준다. D-124: 보스 실패의 대부분이 이쪽이며 실패 문구는 `시간 초과! N초 후 자동 후퇴` |
| 일반 스테이지에서 사망 | — | 재시작 대기 후 자동으로 한 단계 낮은 스테이지에서 파밍(후퇴 모드). 바로 아래가 보스면 그 아래 일반 스테이지(2-1 → 1-9, D-148). 상단 `도전` 버튼이 최초 미클리어 스테이지로 돌아간다 (D-058) |

**게임 오버가 없는 이유.** 필러 P4에 따라 막힘은 파밍 전환으로 흡수된다. 진행도 손실·재화 소실·되돌림은 어떤 경우에도 발생하지 않는다.

입력 장치는 **터치 단일**이다. 가상 조이스틱·가속도계·제스처는 쓰지 않는다.

## Idle RPG Specific Design

### Auto-Combat System

**목적 / 플레이어 체감.** 플레이어가 아무것도 누르지 않아도 히어로가 유능하게 싸우는 것을 보며 "내 성장 결정이 옳았다"를 확인한다.

**규칙**

1. 전투 화면은 세로 화면 상단 약 55% 영역을 차지한다. 히어로는 화면 가로폭의 **왼쪽 30% 지점**에 고정 렌더되고, 전진은 배경 패럴랙스와 적 접근으로 표현한다.
2. 히어로 상태는 5가지다 — 전진(Advance) / 교전(Engage) / 피격(Hit) / 스킬(Skill) / 사망(Dead).
3. **전진 조건:** 화면 내 생존 적이 0마리이고 킬 목표 미달. 이동 속도는 상수 2.0 units/s로 고정되며 어떤 스탯도 이동 속도에 영향을 주지 않는다.
4. **정지(교전 전환) 조건:** 가장 가까운 적이 히어로 공격 사거리 1.6 units 안에 들어온 시점.
5. **적 스폰 규칙:** 화면 오른쪽 경계 밖 +1.5 units 지점에서 등장. 스폰 간격 0.8초, **화면 내 동시 최대 4마리**. 한 스테이지 누적 스폰은 킬 목표와 동일하다.
6. **타겟팅:** 히어로는 항상 자신보다 오른쪽에 있는 적 중 최근접 1체를 타겟한다. 타겟이 사망하면 같은 프레임에 재탐색한다.
7. **공격 판정:** 기본 공격은 단일 대상 근접. 발동 주기는 `1 / 공격속도` 초. 판정은 애니메이션의 히트 프레임 시점에 사거리 재검사 후 적용한다(빗나감 개념은 없음).
8. **적에게 주는 데미지:** `데미지 = max(1, 공격력_총합 × 스킬계수 × 크리배율)`. 적의 방어력은 v1.0에서 0이므로 감쇄가 없다. 크리티컬은 기본 확률 5%, 배율 1.5배이며 Boots 장비 등급으로 확률이 오른다.
9. **적의 공격과 히어로 피격:** 적은 히어로 사거리와 같은 1.6 units에서 1.2초 주기로 반격한다(보스는 1.8초). 공격 주기는 스테이지가 올라도 변하지 않는다 — 난이도는 공격력으로만 표현한다. 피격 데미지는 **비율 감쇄**를 따른다.

   ```
   DEF_REF   = 3 × 적_공격력            (스테이지와 함께 자동으로 커지는 기준값)
   피격데미지 = max(1, 적_공격력 × DEF_REF / (DEF_REF + 방어력_총합))
   ```

   **감산이 아니라 자기 스케일링 비율 감쇄인 이유.** 방어력에서 값을 빼는 감산 방식은 방어력이 적 공격력을 넘는 순간 피격을 최소값 1로 고정해 히어로를 사실상 불사로 만들고, 반대로 적 공격력이 방어력을 추월하는 지점에서는 즉사 절벽을 만든다. 기준값을 고정 상수로 둔 비율 감쇄도 방어력이 승산으로 자라면 같은 불사 문제에 빠진다. 기준값을 적 공격력에 비례시키면 방어력의 **상대 가치**가 전 구간에서 유지되어, 무적 구간과 절벽이 동시에 사라진다. 방어력이 `DEF_REF`와 같을 때 피격은 절반이 된다.
10. **스킬 자동 발동:** 쿨다운이 끝나고 발동 조건(→ Character System 표)이 충족되면 즉시 자동 발동한다. 플레이어가 버튼을 탭하면 조건 검사 없이 즉시 발동한다. 동시에 여러 스킬이 준비되면 슬롯 번호 순으로 0.4초 간격을 두고 발동한다. **쿨다운은 보스전에서만 초기화한다(D-147):** 챕터 보스와 무한의 탑 층은 모든 스킬이 준비된 채 시작하고, 일반 스테이지 사이(이어 달리기·재시작·보스 실패 후 복귀)와 일일 던전 입장은 쿨다운·버프를 그대로 이어 간다.
11. **사망 / 부활:** 히어로 HP가 0이 되면 사망 연출 1.0초 → 실패 판정. 일반 스테이지는 3초 후 같은 스테이지를 처음부터 자동 재시작하며 HP를 전량 회복한다. 부활 아이템·광고 부활은 v1.0에 없다.
12. **보스 규칙:** 챕터의 10번째 스테이지는 보스 단독 1체다. 등장 연출 1.5초(화면 암전 + 보스 이름 배너 + 카메라 셰이크) 후 **30초 제한 타이머**가 시작된다. 보스는 일반 적의 능력치에 보스 배율을 곱한 값을 갖고, 고유 패턴 없이 강한 단일 공격만 한다(패턴은 v1.1).
13. **후퇴(Retreat) 파밍 모드:** 보스 실패 시 팝업에서 `재도전` / `후퇴하기`를 선택한다. 5초 안에 고르지 않으면 자동으로 후퇴한다(D-077, `BOSS_FAIL_AUTO_RETREAT`). 후퇴하면 파밍 스테이지가 직전 일반 스테이지(ch-9)로 고정되고, 상단 스테이지 바에 `보스 재도전` 버튼이 상시 노출된다. 후퇴 상태에서도 골드·EXP는 정상 획득된다.
14. **자동전투 토글 없음.** → `Controls and Input`.

### Character System and Stats

**목적 / 플레이어 체감.** 4개 스탯이 각각 다른 방식으로 전투 시간을 줄여주는 것을 알고, 골드 배분에서 선택의 무게를 느낀다.

**스탯 4종**

| 스탯 | 전투 효과 | 성장 경로 |
|---|---|---|
| **HP** | 최대 체력. 0이 되면 스테이지 실패 | 히어로 레벨(가산), 강화(승산), Armor 장비(승산) |
| **ATK** (공격력) | 기본 공격·스킬 데미지의 기반값 | 히어로 레벨(가산), 강화(승산), Sword 장비(승산) |
| **DEF** (방어력) | 피격 데미지를 비율로 감쇄. 기준값이 적 공격력에 비례해 상대 가치가 유지된다 | 강화(승산), Helm 장비(승산) |
| **공격속도** (Attack Speed) | 초당 공격 횟수. **유일하게 상한이 있는 축** — 최대 3.0회/초 | 강화(가산, 최대 100레벨), Boots 장비 |

**이동 속도는 스탯이 아니다.** 상수 2.0 units/s로 고정한다. 자동 전진 구간에서 이동은 연출이며, 스테이지 진행 속도를 결정하는 것은 DPS다. (기존 3D 구현의 SPD = 이동 속도를 **공격속도로 재정의**한 것이다.)

**합산 순서 — 기본값에 AP 가산(D-141), 그 위에 강화·장비·버프 승산**

```
ATK_total      = (ATK_기본(10)  + 0.25 × 주스탯AP) × 1.16^upgradeAtkLevel × Sword등급배율 × (1 + Σ 버프배율)
HP_total       = (HP_기본(100)  + 5 × 활력AP)       × 1.16^upgradeHpLevel × Armor등급배율
DEF_total      = DEF_기본(20)                      × 1.16^upgradeDefLevel × Helm등급배율
공격속도_total  = (1.0 + 0.02 × upgradeSpdLevel) × (1 + Boots공격속도보너스)   — 상한 3.0
크리확률_total  = 5% + 2%p × upgradeCritLevel + Boots크리보너스 (+ 특성·직업)
크리피해        = 1.5 + 0.1 × upgradeCritDmgLevel (+ 반지·특성·직업)
```

레벨 1에는 AP가 없어 기본값 그대로다. AP를 자동으로 나누면(주 스탯 2 : 활력 1) 레벨당 ATK +0.5·HP +5로 D-053의 레벨 보너스와 같다. 방어력은 승산 대상이므로 기본값이 0일 수 없어 20에서 시작한다.

**직업별 스탯 이름 (D-140).** 공격 스탯은 안에서 하나(ATK)지만 직업 계열마다 이름이 다르다. 전사 계열(초보자 포함)은 힘 → **공격력**·무기 **검**, 마법사 계열은 지능 → **주문력**·무기 **지팡이**, 궁수 계열은 민첩 → **공격력**·무기 **활**. 문자열 표의 `{atk}`·`{main}`·`{weapon}`이 부팅과 전직 때 영웅의 계열 단어로 바뀌어 스탯 칩·능력치 줄·스킬 설명("주문력의 300% 피해")·장비 효과·펫 문구가 함께 바뀐다. 무기 칸 아이콘도 계열에 맞춰 지팡이 7종·활 7종을 쓴다(장비 id는 `sword_*` 그대로라 저장과 확률은 바뀌지 않는다).

**레벨업 AP (D-141, 메이플 키우기식).** 레벨업마다 AP 3을 받는다. 주 스탯(힘/지능/민첩)은 1당 기본 ATK +0.25(기본값의 +2.5%), 활력은 1당 기본 HP +5(+5%). 캐릭터 창 `스탯` 페이지에서 남은 AP·주 스탯·활력과 효과(예: `주문력 기본값 +405%`)를 본다.

1. **자동 분배(기본):** 레벨업 즉시 주 스탯 2 : 활력 1로 나눈다. 시뮬레이션은 이 모드다.
2. **직접 분배:** 버튼으로 전환하면 새 AP가 쌓이고 `+1`(누르고 있으면 연속)·`+10`으로 나눈다. 남은 AP가 있으면 탭에 빨간 점. 다시 자동으로 바꾸면 남은 AP만 자동 비율로 나눈다(이미 나눈 것은 그대로).
3. **초기화:** 직접 분배 모드에서 젬 50으로 모든 AP를 돌려받는다.
4. **기존 저장:** AP 필드가 없는 저장은 부팅 때 지난 레벨 전부를 자동 비율로 받는다 — 스탯이 바뀌지 않는다.

**강화가 가산이 아니라 승산인 이유.** 적 능력치가 스테이지 인덱스에 대해 지수로 자라므로, 플레이어 파워도 지수로 자라야 한다. 강화 비용이 지수(`1.12^레벨`)이면 강화 레벨은 누적 골드의 로그이고 누적 골드는 지수이므로 **강화 레벨은 스테이지에 선형**이다. 따라서 레벨당 효과가 가산이면 파워는 선형에 머물고 지수 난이도를 영구히 따라잡지 못한다. 레벨당 효과를 승산으로 두면 파워가 `1.16^(선형)` = 지수가 되어 난이도와 같은 차원에서 경쟁한다. 이 때문에 HP·ATK·DEF 강화에는 **최대 레벨 상한을 두지 않는다.**

버프배율(승산)은 스킬 `전투 함성`과 광고 골드 부스터처럼 시간제 효과만 해당하며 서로 **합산 후 1회 승산**한다(중첩 곱셈 금지).

**히어로 레벨 (EXP)**

1. 적을 처치할 때마다 EXP를 얻는다. 보스는 일반 적의 5배.
2. 레벨업 요구 EXP는 `200 × 1.18^(level−1)`이며 상한이 없다 (D-083).
3. 레벨업 시 AP 3을 얻는다(D-141, 자동 분배면 HP +5·ATK +0.5와 같다). 전투 중이면 즉시 적용된다. 연출은 히어로 발밑 링 이펙트 + 토스트 1줄.
4. 레벨업은 플레이어 선택이 아니다 — 자동이며, 이것이 "방치만 해도 세진다"의 최소 보장선이다.
5. 스킬 **슬롯** 해금은 히어로 레벨로 게이트한다 (Lv1 / 5 / 12 / 20 / 30 / 45, D-078).

**스킬 (D-078 — 장르 표준 스킬 소환·도감)**

스킬은 24종(등급별 6종)의 **도감**이다. 소환으로 모으고, 6칸 슬롯에 장착한 스킬이 슬롯 순서대로 자동 발동한다. 데이터 원본은 `Core/Skills/SkillCatalog`(스킬별 수치), 등급 경제는 아래 상수표.

> **현재 (D-104 · D-107 · D-109):** 시작 스킬 3종(초보자 전용) + 계열(전사·마법사·궁수)마다 **16종(등급별 4)** = **51종**. 전직 후엔 자기 계열만 장착·소환한다. 아래 표는 D-078 당시 24종 목록이며, 계열 배정과 이후 추가분은 결정 로그와 `SkillCatalog`가 원본이다.

2. **자동 발동:** 공격·버프는 사거리 안에 적이 있으면, 회복은 HP가 임계치 이하일 때. 동시에 준비되면 슬롯 순 0.4초 간격. 탭하면 조건 없이 즉시 발동(공격 스킬은 사거리 안 적 필요).
3. **소환:** 스킬 4등급 확률표(C 55 / R 33 / E 10 / L 2 %)와 100회 천장, 천장 카운터는 따로(D-113부터 장비 7등급 표와 분리). 등급을 먼저 뽑고 등급 안에서 균등. 새 스킬은 빈 해금 슬롯에 자동 장착.
4. **중복:** 레벨 +1(최대 10). 최대 레벨이면 등급별 골드 환급.
5. **레벨업:** 골드로도 올린다. 비용 `SKILL_UPG_BASE_{등급} × 1.15^(level−1)`. 레벨당 모든 % 수치 +10%p(레벨 10 = ×1.9).
6. **보유 효과:** 보유한 스킬마다 공격력 +`SKILL_OWNED_ATK_{등급}`% × 레벨 배율. 장착 여부와 무관.
7. **장착:** 스킬 패널에서 선택 → 장착(빈 슬롯 없으면 교체할 슬롯 선택) / 해제 / 자동 장착(등급 → 레벨 순). 전생 시에도 도감은 유지.

### Inventory, Equipment and Gacha

**목적 / 플레이어 체감.** 뽑기 결과 하나가 전투 시간을 눈에 띄게 줄이는 것을 보고, 다음 뽑기를 하고 싶어진다.

#### 장비 구조

8슬롯 × 7등급 = **56종** (D-109: 장비 4 + 장신구 4, D-113: 등급 7단계). 슬롯마다 담당 스탯이 다르므로 8슬롯을 모두 올려야 전투가 균형 있게 개선된다. 강화(중복)는 슬롯 효과의 가산분과 보유 효과에 똑같이 `×(1 + EQUIP_ENHANCE_GAIN)^레벨`로 붙는다.

**등급 7단계 (D-113):** 일반 Common · 고급 Uncommon · 희귀 Rare · 영웅 Epic · 전설 Legendary · 신화 Mythic · 고대 Ancient. 장비와 펫(D-114)이 7단계이고 스킬·직업은 4단계(일반·희귀·영웅·전설)를 유지하며 같은 이름의 색·테두리를 쓴다. 저장 id `Equipment_{Slot}_{Grade}`에서 기존 네 등급의 이름은 그대로라 옛 저장이 유효하다.

#### 장착과 중복 처리

1. **자동 장착:** 획득 장비의 등급이 해당 슬롯 현재 장착품보다 높으면 즉시 자동 장착하고 "자동 장착됨" 토스트를 띄운다. 같거나 낮으면 인벤토리로 들어가며 "인벤토리에 보관" 토스트를 띄운다.
2. **수동 장착:** 장비 패널의 인벤토리 목록에서 슬롯을 탭해 언제든 교체할 수 있다. 하향 장착도 허용한다(플레이어 결정을 막지 않는다).
3. **중복 처리 = 강화 (D-062):** 이미 보유한 동일 장비를 다시 뽑으면 그 장비의 **강화 레벨이 +1** 오른다(최대 `EQUIP_MAX_LEVEL` 10). 강화 1레벨당 등급 기본 효과가 `×(1 + EQUIP_ENHANCE_GAIN)`(10%) 승산으로 커진다 — 강화 10이면 기본 효과의 약 2.6배. 이미 최대 레벨이면 **골드로 환급**된다 — 일반 20 / 고급 40 / 희귀 80 / 영웅 250 / 전설 1,000 / 신화 4,000 / 고대 15,000골드(D-115: 소환 레벨이 최대여도 다 키운 수집의 평균 환급이 10연 1회 단가의 절반 미만 — 그 이상이면 뽑을수록 골드가 남는 구조가 된다). 중복은 인벤토리를 늘리지 않는다. 강화 레벨은 장비마다 따로 저장되며 교체해도 유지된다.
4. **인벤토리 상한:** 없다. 장비 종류가 56종으로 고정이고 중복은 강화·환급으로 처리되므로 보유 목록은 최대 56개다.
5. **승급 (D-116, 장르 표준 장비 합성):** 최대 강화(+10) 장비는 골드를 내고 같은 슬롯의 한 등급 위 장비로 승급한다. 영웅까지만(`EQUIP_PROMOTE_MAX_GRADE`) — 전설 이상은 뽑기로만 얻는다. 비용 `500 × 3^등급`(일반→고급 500 / 고급→희귀 1,500 / 희귀→영웅 4,500). 승급한 장비는 +0으로 돌아가 보유 상태로 남고(다시 중복으로 강화된다), 윗등급 장비는 없으면 +5로 얻고 있으면 +5 강화된다(최대 10). 원래 장비를 끼고 있었으면 윗등급으로 바꿔 낀다. 장비 창 아래 `일괄 승급` 버튼이 낮은 등급부터 골드가 되는 만큼 승급한다. 소켓·재감정은 없다.

#### 가챠 (등급별 확률표 + 천장)

**규칙**

1. 1회 뽑기 비용은 **골드 150**, 10연은 **골드 1,350**(10% 할인)이다(D-113: 500 / 4,500에서 인하 — 확률을 낮춘 만큼 많이 뽑는다). 10연은 젬 **200**으로도 가능하다.
2. 뽑기는 슬롯을 먼저 균등 확률(8슬롯 각 12.5%, D-109)로 고르고, 등급을 **확률표**로 고른다. 슬롯과 등급이 정해지면 장비는 1종으로 확정된다.
3. **등급 확률표 (D-113):** 일반 **60 %** / 고급 **28 %** / 희귀 **9 %** / 영웅 **2.5 %** / 전설 **0.45 %** / 신화 **0.045 %** / 고대 **0.005 %**. 합은 항상 100 %이며, 이 표가 그대로 게임 내 공시표다(이전 4등급 55 / 33 / 10 / 2 %는 스킬 소환에만 남는다). pity 누적은 확률을 바꾸지 않는다 — 방식은 장르 표준(등급별 확률표 + N회 천장)이다.
4. 등급 추첨은 [0, 1) 균일 난수 하나를 확률표의 누적 합과 비교해 결정한다. 다른 분포·가중치·보정은 쓰지 않는다.
5. **천장:** pity 카운터가 200(`GEAR_PITY`, D-113, 이전 100)에 도달하는 뽑기는 등급 판정을 건너뛰고 전설을 확정 지급한다. D-123: pity 카운터는 소환 단계가 전설을 연 뒤의 뽑기만 센다(전설이 나올 수 없는 단계에는 천장이 없다).
6. **천장 리셋:** 전설 이상(전설·신화·고대)을 획득하면 천장·자연 획득을 가리지 않고 pity 카운터를 0으로 리셋한다 (장르 표준). 천장 전 자연 Legendary로 카운터가 유지되던 초안 규칙(D-017)은 폐기한다.
7. pity 카운터는 1회·10연 구분 없이 뽑기 1건당 1 증가한다. 10연은 10건으로 계산되며 그 안에서 천장이 걸릴 수 있다.
8. **확률 공시:** 가챠 패널에 등급별 확률(장비 7등급을 등급 색으로 두 줄, 스킬 4등급)과 천장·리셋 규칙을 게임 내에서 열람할 수 있게 한다. 공시표는 실제 추첨에 쓰는 확률표와 같은 데이터에서 그려지며, 검증기 실측(10만 회)과 오차 1%p 이내여야 한다.
9. **진행도 노출:** 가챠 패널 상단에 `천장까지 N회` 게이지를 상시 표시한다. 필러 P3의 핵심 표현이다. D-123: 전설이 열리기 전에는 같은 자리에 소환 단계 게이지(`소환 Lv N · 다음 단계까지 M회`)를 보여 준다.
10. **소환 레벨 (D-115, 장르 표준):** 장비·스킬·펫 소환마다 누적 뽑기 수로 소환 레벨이 오른다(최대 10). 레벨 L은 누적 `단계 × (L−1) × L / 2`회 — D-123: 장비 단계 100(Lv 2 100 · Lv 3 300 · Lv 4 600 · Lv 5 1,000 · … · Lv 10 4,500, 단계마다 수백 회), 펫 50(Lv 2 50 · Lv 5 500), 스킬 20(Lv 2 20 · Lv 4 120; 1회 가격이 장비의 33배라 횟수는 적다). 레벨마다 희귀 이상(스킬은 영웅 이상) 확률이 `× (1 + 0.12 × (L−1))`(Lv 10이면 ×2.08)로 오르고 일반이 그만큼 줄어 합은 100 %를 유지한다. 저장 필드 없이 뽑기 카운터에서 계산한다. 천장 규칙은 레벨과 무관하다.
11. **등급 개방 (D-121 → D-123, 메이플 키우기 방식):** 소환 단계가 등급을 연다. **1단계는 일반만**, 2단계 고급, 3단계 희귀, 4단계 영웅, 5단계 전설, 6단계 신화, 7단계 고대(장비 누적 100 / 300 / 600 / 1,000 / 1,500 / 2,100회, 펫 50 / 150 / 300 / 500 / 750 / 1,050회). 스킬은 1단계 일반, 2단계 희귀, 3단계 영웅, 4단계 전설(20 / 60 / 120회). 열리지 않은 등급은 0 %이고 그 몫은 일반이 가진다. 골드·젬·광고 무료 소환·환영 선물 모두 같은 표를 쓴다(환영 선물 10연은 일반 10개). 8~10단계는 확률만 오른다.
12. **공시:** 확률표는 지금 소환 레벨의 표를 보여 준다. 전설이 열리기 전에는 윗줄이 `소환 Lv N에서 X 등급 개방`, 연 뒤에는 `소환 Lv N · M회 더 뽑으면 X 등급 개방`. 열리지 않은 등급은 확률 대신 `Lv N 개방`을 흐리게 쓰고, 천장 줄은 `전설 등급이 열리면(소환 Lv 5) 200회째 전설 확정`. 단계가 오르면 토스트(`장비 소환 Lv 2 달성! 고급 등급이 열렸어요`).
13. **승급(D-116)은 단계와 별개의 확정 경로**다: +10 장비를 골드로 한 등급 올리므로 1단계에서도 일반을 고급으로 만들 수 있다(영웅까지).

#### 펫 (D-114, D-102 동료의 확장)

**목적 / 플레이어 체감.** 영웅 어깨 뒤를 따라다니며 함께 싸우는 작은 펫을 모으고 키운다. 장비·스킬과 나란한 세 번째 수집 축이다(장르 표준: 버섯커 키우기·세나 키우기의 펫 소환).

1. **종류:** 16종, 장비 7등급 사다리에 위로 갈수록 적게 — 일반 3(슬라임·병아리·토끼) / 고급 3(개구리·박쥐·아기 돼지) / 희귀 3(정령·여우·펭귄) / 영웅 3(부엉이·마법 고양이·바다거북) / 전설 2(아기 용·불사조) / 신화 1(구미호) / 고대 1(청룡). 수치 원본은 `Core/Pets/PetCatalog`.
2. **획득 = 펫 소환:** 소환 화면의 세 번째 탭. 1회 300골드 / 10회 2,700 / 10회 200젬. 확률은 장비 7등급표(60 / 28 / 9 / 2.5 / 0.45 / 0.045 / 0.005 %)와 200회 천장(전설 확정, 전설 이상이면 초기화)을 쓰고 천장 카운터·소환 레벨은 따로 센다(등급 개방은 장비와 같은 단계, D-123: 1단계 일반만). 등급을 먼저 뽑고 등급 안에서 균등. **1장 보스(1-10)를 처치하면 열린다**(`PET_UNLOCK_STAGE`) — 첫 5분은 강화에 집중.
3. **전투:** 장착한 1마리가 영웅 뒤를 떠다니며 사거리 안 가장 가까운 적을 `영웅 공격력 × 공격 배율 × 레벨 배율 × 강화 배율`로 일정 간격마다 친다. 펫마다 화상·중독·기절이 붙고 스킬 콤보(파쇄·점화)에 걸린다.
4. **성장:**
   - 골드 레벨업(최대 50): 비용 `500 × 1.6^등급 × 1.15^(레벨−1)`. 레벨마다 공격 ×1.1, 보유 효과 +10%(선형).
   - 중복 = 강화 +1(최대 10, 공격·보유 효과 ×1.1/강화). 최대 강화 뒤 중복은 환급 30 / 60 / 120 / 500 / 2,000 / 8,000 / 30,000골드(소환 레벨이 최대여도 최대 상태 평균 환급이 10연 1회 단가의 절반 미만 — 그 이상이면 뽑을수록 골드가 느는 구조가 된다, D-115).
5. **보유 효과:** 가진 펫마다 장착과 무관하게 공격력 +2 / 3 / 5 / 8 / 15 / 30 / 60 %(등급별) × 강화 × 레벨. 장비 56종보다 종류가 적은 만큼 한 마리의 값이 크다.
6. **자동 장착:** 새 펫이 장착 펫보다 등급이 높으면 바로 장착(장비와 같은 규칙). 펫 창에서 언제든 바꿀 수 있다.
7. **펫 창(오른쪽 메뉴 "펫"):** 위에 선택한 펫(받침대 위 애니메이션, 등급·레벨·강화, 공격·보유 효과, 장착·레벨업), 보유 효과 합계, 4×4 도감(미보유는 실루엣), 아래에 펫 소환 바로가기.
8. **옛 저장:** D-102 동료(스테이지로 합류)를 이미 얻은 저장은 그 펫과 레벨을 그대로 가진 채 이어진다. 이후 펫은 소환으로만 얻는다.

### Automation and Offline Progression

**목적 / 플레이어 체감.** 앱을 껐던 시간이 손실이 아니라 저축이었다고 느낀다.

**자동화 계층**

| 계층 | 자동화 대상 | 플레이어 개입 |
|---|---|---|
| A-1 | 전투 (이동·타겟팅·기본 공격) | 없음 — 항상 자동 |
| A-2 | 스킬 발동 | 자동. 탭으로 즉시 발동만 선택적 |
| A-3 | 스테이지 진행 (클리어 → 다음 스테이지) | 없음 — 클리어 후 2초 뒤 자동 진행 |
| A-4 | 히어로 레벨업 | 없음 — 조건 충족 시 자동 |
| A-5 | 장비 장착 (상위 등급 획득 시) | 없음 — 자동 장착 |
| A-6 | 중복 장비 강화 / 최대 레벨 환급 | 없음 — 자동 |
| **수동으로 남기는 것** | 강화 / 가챠 / 스킬 레벨업 / 파밍 스테이지 선택 / 광고 시청 | **전부 플레이어 결정** |

자동 강화·자동 가챠는 v1.0에 넣지 않는다. 그것까지 자동화하면 플레이어가 할 일이 사라져 필러 P4(선택의 무게)가 무너진다.

**오프라인 진행 규칙**

1. 앱이 백그라운드로 가거나 종료될 때 UTC Unix 초를 저장한다. 복귀 시(콜드 스타트와 백그라운드에서 돌아올 때 모두, D-133) 현재 UTC와의 차이를 경과 시간으로 쓴다. 시각은 **신뢰 시각**이다: 서버 시각(Firebase)에 맞춘 기준점 + 기기 절전에도 흐르는 단조 시계라 기기 시계를 바꿔도 움직이지 않는다.
2. **상한 21,600초(6시간).** 초과분은 버린다. 상한은 팝업에 "최대 6시간" 문구와 게이지로 항상 보여준다.
3. **초당 획득량은 현재 파밍 스테이지에 연동된다:** `오프라인골드_초당 = 파밍스테이지_골드보상 / 3000`. 스테이지 클리어 목표 시간이 25초이므로 이는 온라인 수급의 **약 0.8% 효율**이며, 6시간 상한을 다 채우면 온라인 약 3분에 해당하는 양이다. 하루 4세션이면 세션 사이 오프라인이 하루 약 20시간이므로, 합계는 전체 골드 수입의 약 35~40%가 된다(D-055). 진행할수록 방치 수익도 함께 커진다.

   **오프라인은 보조 수입이다.** 주 수입은 앱을 열고 진행하는 온라인 파밍이며, 오프라인은 "다시 켤 이유"를 만드는 복귀 보너스로 설계한다. 효율을 높게 잡으면 6시간 방치 한 번이 그 지점까지 온라인으로 번 누적 골드를 수십 배 넘어서면서, 진행·강화·가챠 선택이 전부 무의미해진다. 낮은 효율 × 스테이지 연동 × 6시간 상한 세 장치가 함께 그것을 막는다.
4. 최소 경과 시간 **60초** 미만이면 팝업을 띄우지 않고 골드만 조용히 지급한다.
5. **광고 2배:** 팝업에 `수령`과 `광고 보고 2배 수령` 두 버튼을 둔다. 2배는 계산된 골드에만 적용되며 상한 자체를 늘리지 않는다.
6. 오프라인 중에는 EXP·스테이지 진행·장비 획득이 없다. 골드만 쌓인다.
7. **시간 조작 방어 (D-133):** 보상은 신뢰 시각으로만 계산한다. 로그인했는데 서버 시각을 아직 모르면(네트워크 없음) 보상을 미뤘다가 연결되면 돌아온 순간 기준으로 지급한다. 서버 시각으로 본 경과가 음수(미래 종료 시각)면 0으로 처리하고 기준 시각을 서버 시각으로 재설정한다. 로컬 모드(Firebase 없음)는 기기 시각을 쓰되 종료 시각이 뒤로 가지 않아, 시계를 앞뒤로 돌려도 같은 시간을 두 번 받지 못한다. 상한을 넘은 긴 부재는 상한만큼 준다(이전의 "상한 2배 초과 → 0"은 하루 쉬고 온 플레이어도 0으로 만들어 폐지). 크래시나 에러 팝업 없이 조용히 방어한다.

### Upgrade Trees

**목적 / 플레이어 체감.** 골드를 어디에 넣을지 매번 조금씩 고민하게 만든다. 잘못된 선택은 없지만, 더 나은 선택은 있다.

**구조 — 트리가 아니라 6개의 독립 레인이다(D-142).** 분기·선행 조건·상호 배타 선택을 두지 않는다. 방치형에서 되돌릴 수 없는 분기는 정보 부족 상태의 플레이어를 처벌하기 때문이다. 캐릭터 창 `능력치` 페이지에 2열 × 3행 카드로 놓이고, 이름은 직업 단어를 따른다(D-140, 마법사는 `주문력`).

| 레인 | 레벨당 효과 | 기준 비용(baseCost) | 최대 레벨 | 열림 |
|---|---|---|---|---|
| HP 강화 | 최대 HP **×1.16** (승산) | 300 골드 | 없음 | 처음부터 |
| ATK 강화 | 공격력 **×1.16** (승산) | 450 골드 | 없음 | 처음부터 |
| DEF 강화 | 방어력 **×1.16** (승산) | 450 골드 | 없음 | 처음부터 |
| 공격속도 강화 | 공격속도 +0.02 회/초 (가산) | 600 골드 | **100** (상한 3.0회/초) | 처음부터 |
| 치명타 확률 (D-142) | 치명타 확률 **+2%p** (가산) | 300 골드 | **25** (+50%p) | 영웅 Lv 15 |
| 치명 피해 (D-142) | 치명타 피해 **+10%p** (가산) | 300 골드 | 없음 | 영웅 Lv 25 |

**치명타가 모든 영웅 피해에 붙는다 (D-142).** 주공격뿐 아니라 스킬 타격과 펫 공격도 영웅의 치명타 확률·피해로 치명타를 굴린다(도트는 제외). 스킬 치명타는 치명타 숫자로 보이고 효과는 스킬 수준(소리는 한순간에 한 번)이라 광역 스킬이 화면을 흔들지 않는다. 치명타 줄 두 개는 서로를 키운다 — 확률만 높으면 피해가 1.5배에 머물고, 피해만 높으면 터지지 않는다.

**한계 돌파 (D-143).** 모든 레인은 10레벨마다(10·20·30 …) 멈춘다. `돌파` 버튼(주황, 돌파석 아이콘)으로 돌파석을 쓰면 다음 10레벨이 열린다. k번째 돌파는 돌파석 `10 × k`개(10·20·30 …). 돌파석은 일일 던전 한 판마다 2개, 무한의 탑 층마다 1개(10층마다 +5)로 얻는다. 시뮬레이션(매일 던전·탑) 플레이어는 7일차까지 돌파 5회 안팎, 돌파석이 30~40개 남는다 — 성실한 플레이어는 막히지 않고, 6줄을 고르게 올리면 던전·탑이 필요해진다. 돌파 가능한 줄이 있으면 캐릭터 탭에 빨간 점.

**비용 공식:** `다음레벨비용 = baseCost × 1.12^현재레벨`

기존 구현의 선형 공식(`baseCost × (level+1)`)과 최대 레벨 50은 폐기한다. 선형 비용은 방치형 골드 수급이 지수로 커지는 구간에서 즉시 상한에 닿아 골드 싱크 역할을 못 한다.

**왜 상한이 없고, 왜 그래도 무한히 세지지 않는가.** HP·ATK·DEF는 상한이 없지만 레벨 하나의 가격이 `1.12^레벨`로 오르므로 실제 도달 레벨은 누적 골드의 로그다. 반면 **파밍 시간은 매우 효율적으로 파워로 환산된다** — 파밍 시간을 k배 늘리면 골드가 k배가 되고 도달 레벨이 `log₁.₁₂ k`만큼 오르므로 파워는 `k^(ln1.16/ln1.12) ≈ k^1.31`배가 된다. 즉 벽 앞에서 40% 더 파밍하면 파워가 약 1.56배가 된다. 이것이 필러 P4의 "파밍으로 돌파"가 실제로 작동하는 메커니즘이다.

**공격속도만 상한이 있는 이유.** 공격속도를 승산으로 두면 공격 판정과 애니메이션이 성립하지 않는 값(초당 수십 회)에 도달한다. 상한 3.0회/초는 히트 프레임이 구분되는 최대치이며, 대신 공격속도는 가산으로 두어 초반 체감을 크게 만든다.

**시너지.** 레인 간 명시적 시너지 버튼은 없지만 수식상 곱으로 작동한다 — ATK 강화와 공격속도 강화는 DPS에서 곱해지고, HP 강화와 DEF 강화는 생존 시간에서 곱해진다. 플레이어는 "공격 두 축을 같이 올려야 DPS가 뛴다"를 체감으로 학습한다.

**해금 조건.** 기본 4개 레인은 첫 실행부터 열려 있어 첫 세션에서 선택의 즐거움을 바로 준다. 치명타 두 줄은 영웅 Lv 15·25에 열린다(D-142). 레벨 한계는 돌파석으로 연다(D-143).

**메타 업그레이드.** 프레스티지(환생)와 그 영구 배율은 D-126에서 제외했다. → `Meta-Progression`.

| 상황 | 처리 |

### 특성 트리 (D-087)

**목적.** 스킬은 소환으로 얻고, 특성은 플레이어가 직접 고른다. 레벨업마다 1포인트를 받아 공격·수호·비전 세 갈래 중 원하는 곳에 찍는다. 버섯커 키우기의 특성 관습을 따른다.

**구조.** 갈래마다 4단계. 1·2단계는 노드 2개, 3단계는 1개, 4단계는 1랭크짜리 핵심 특성이다. 단계 t는 같은 갈래에 `t × TALENT_TIER_STEP` 포인트를 써야 열린다. 초기화는 `TALENT_RESET_GEM` 젬으로 모든 포인트를 돌려받는다. 수치 원본은 `Core/Talents/TalentCatalog`.

| 갈래 | 1단계 | 2단계 | 3단계 | 핵심 |
|---|---|---|---|---|
| 공격 | 예리함 공격력 +2%/랭크 · 정밀 치명타 +1%p | 흉포 치명 피해 +8%p · 신속 공격속도 +2% | 거인 사냥꾼 보스 피해 +5% | 처형: HP 30% 미만 적에게 +50% |
| 수호 | 활력 HP +3% · 강철 피부 방어력 +3% | 인내 받는 피해 -2% · 치유술 회복·보호막 +10% | 강인함 HP +5% | 최후의 저항: 스테이지당 1회 치명타를 HP 30%로 버팀 |
| 비전 | 집중 스킬 피해 +4% · 가속 쿨타임 -2% | 지속 버프 시간 +8% · 맹독 DoT +10% | 숙련 스킬 피해 +6% | 과부하: 피해 스킬 4번째 발동마다 ×2 |

일반 노드는 최대 5랭크. 전부 찍으려면 78포인트(레벨 79)가 필요하다. 스탯 순서는 `(기본+레벨) × 강화 × 장비 × 보유효과 × (1+특성) × (1+버프)`. 받는 피해 감소와 쿨타임 감소는 각각 최대 50%.

**저장.** `talentIds` / `talentRanks`(인덱스 정렬). 특성 배우기와 초기화는 플레이어 결정이므로 저장을 요청한다.

**밸런스.** 시뮬레이터는 고정 배분 순서(`SimSpender.TalentPlan`)로 포인트를 쓴다. 특성 도입 후 무광고 7일차 5-6~5-8(도입 전 5-3~5-6), V-1 목표 범위 유지.

### Number Balancing

**목적.** 모든 수치의 단일 출처. 다른 섹션은 여기의 상수·공식 이름으로만 참조한다.

**표기 체계 (D-127).** 1,000 미만은 정수 그대로, 1,000부터는 **유효숫자 3자리 + 단위**에 끝의 0을 지운다 — `1K`, `1.35K`, `12.3K`, `123K`, `1.23M`, `2.5B`, `1T`. T를 넘는 값은 `aa`, `ab` … 순의 알파벳 접미어로 이어간다. 자릿수는 버린다(반올림하지 않는다) — 보이는 값이 실제보다 크지 않게. 가격·진행 수치·보상까지 모든 숫자가 같은 규칙을 쓴다(`BigNumberFormat`).

**전역 스테이지 인덱스.** 모든 스케일링은 `g = (챕터 − 1) × 10 + 스테이지` 하나를 기준으로 한다. 챕터별 별도 테이블을 두지 않으므로 무한 확장이 자동으로 성립한다.

**벽이 생기는 두 가지 이유(의도).**

1. **수입 성장률이 난이도 성장률보다 낮다.** 적 HP는 `1.14^g`, 스테이지 골드는 `1.04^g`(D-122: `1.035^g`)로 자란다. 골드를 파워로 바꾸는 효율 지수가 1.31이므로 비교는 `1.04^1.31 ≈ 1.053` 대 `1.14`이다. 초안의 `1.08^1.31 ≈ 1.106`은 적 HP `1.10`을 **앞질러** 벽이 생기지 않았다(시뮬레이션 1차, D-053).
2. **보스가 불연속 요구를 만든다.** 보스는 같은 구간 일반 적의 15배 HP(D-124: 26배, 공격은 0.5배 — 실패는 대부분 시간 초과)를 30초 안에 처리해야 하므로 일반 스테이지의 약 1.6배 DPS를 요구한다. 이것이 챕터마다 반복되는 명확한 관문이다.

**돌파 수단은 파밍 시간이다.** 파밍 시간을 k배 늘리면 골드가 k배 되고 강화 도달 레벨이 `log₁.₁₂ k` 올라 파워가 `k^1.31`배가 된다. 보스가 요구하는 1.6배 헤드룸은 약 **40% 더 파밍**하면 채워진다. 벽이 영구적이지 않고, 동시에 공짜도 아니다 — 필러 P4가 성립하는 지점이다.

정체 구간의 위치와 파밍 소요 시간은 시뮬레이션으로 확정한다(→ V-1, V-6).

**소프트캡과 시간 게이트.** 하드 게이트(레벨 제한·입장권·스태미나)를 두지 않는다. 진행 억제는 전부 수치 곡선과 6시간 오프라인 상한으로만 한다.

2. **보상:** 층마다 젬 `3 + 0.1 × N`(내림)과 돌파석 1(D-143, 10층마다 +5), 5층마다 장비 소환권 ×5, 10층마다 스킬·펫 소환권 ×2. 처음 깬 층만 보상(최고 층 다음부터 도전).
3. **열림:** 1장 보스(1-10) 처치 후. 진행 중에는 던전 배너가 `무한의 탑 N층 · 남은 시간 · 젬 +X`를 보여 주고 상단 판이 `탑 N층`이 된다. 층마다 `N층 돌파! 젬 +X` 토스트.
4. **시뮬레이션:** 세션마다 한 번 오르는 플레이어가 7일차 40~44층(스테이지보다 약 12단계 뒤). 층 보상을 젬 10 + N으로 두자 7일 진도가 6-5까지 올라 지금 값으로 낮췄다. D-144·D-145 뒤에는 7일차 26~35층 — 체력 2배라 층 N의 벽이 스테이지 `4 + N + 3.6`과 같아 본 진행과 같은 높이의 도전이 된다.

**클리커·능동 상호작용에 대한 명시적 이탈.** Idle/Incremental 장르 가이드는 `Core Click/Interaction`(클릭 액션, 클릭 파워 성장, 오토클리커 해금, 콤보/연타)을 필수 서브섹션으로 요구한다. **SoloHero는 클리커 메카닉을 채택하지 않는다.** 근거는 필러 P1과 확정 결정 D5(조작 최소)이며, 장르 관습을 몰라서 빠뜨린 것이 아니다. 대체 상호작용은 **스킬 버튼 수동 탭**(선택적, 3개 버튼)이며 이것이 유일한 전투 입력이다. 클릭 파워 성장에 해당하는 축은 스킬 레벨업이 대신한다.

## Progression and Balance

### Player Progression

플레이어 파워는 5개 축에서 자란다. 축마다 획득 방식과 체감 주기가 다르다.

| 축 | 획득 방식 | 플레이어 개입 | 체감 주기 | 기여 형태 |
|---|---|---|---|---|
| 히어로 레벨 | 적 처치 EXP | 없음(자동) | 초반 1~2분, 후반 수십 분 | HP·ATK 가산 |
| 스탯 강화 4종 | 골드 소비 | **선택** | 즉시 | HP·ATK·DEF 승산, 공격속도 가산 |
| 장비 8슬롯 (D-109) | 가챠 | **선택** | 뽑기 단위, 간헐적 대폭 상승 | 스탯 승산·보유 효과 |
| 스킬 도감 | 소환(확률) + 슬롯 해금(레벨) + 골드 레벨업 | **선택·확률** | 레벨업·소환 단위 | 버스트 데미지·버프·보유 효과 |
| 파밍 스테이지 | 최고 도달 이하 자유 선택 | **선택** | 즉시 | 골드·EXP 수급률 |

**성장의 리듬.** 자동 축(레벨)이 바닥을 보장하고, 선택 축(강화·스킬)이 꾸준한 우상향을 만들며, 확률 축(장비)이 불규칙한 점프를 준다. 셋이 합쳐져 "매 세션 뭔가 달라졌다"를 만든다.

**보이는 성장과 다음 목표 (D-111).** 모든 축의 결과는 HUD의 **전투력** 숫자 하나로 모이고(`CombatPower`: 공격력 × 공속 × 치명 기대값 + 체력 + 방어력의 가중합), 오를 때마다 초록 "+N"이 떠오른다. **D-127 전투력 시스템:** 전투력 칸 아래에 지금 싸우는 스테이지·보스·탑 층의 **권장 전투력**(`150 × 1.15^(g−1)`, 보스 ×1.1 — 시뮬레이션에서 처음 클리어할 때의 전투력 중앙값에 맞춘 값)을 쓰고, 넘으면 초록·모자라면 빨강으로 보인다. 숫자는 새 값까지 올라가며(카운트업) 5 % 이상 크게 오르면 화면 가운데에 `전투력 상승! 3.1K ▶ 3.4K` 배너가 뜬다. 보스 등장 배너와 탑 창에도 권장 전투력이 나온다. **가이드 퀘스트 바**(왼쪽 레일 아래)는 항상 다음 할 일 하나와 보상을 보여 준다 — 강화 → 소환 → 1장 보스 → 전직 → 스킬·특성 → 2차 전직으로 이어지는 28단계 연쇄 후, 스테이지·강화·소환·레벨 목표가 커지며 순환한다. 완료되면 금빛으로 맥동하고 탭하면 보상(젬 또는 파밍 스테이지 클리어 n회분 골드), 미완료면 탭으로 해당 탭에 바로 간다. 첫 접속은 로딩 직후 환영 선물(골드 + 무료 소환 카드 연출)과 강화 버튼을 가리키는 손가락으로 시작한다.

**첫 30분 진행 시나리오 (설계 의도)**

| 경과 | 플레이어 상태 | 무엇을 배우는가 |
|---|---|---|
| 0~1분 | 전투 자동 시작, 1-1 클리어, 골드 50 획득 | 내가 안 눌러도 진행된다 |
| 1~3분 | 튜토리얼 힌트 1 → 가챠 1회 → Common 무기 자동 장착 | 뽑으면 바로 세진다 |
| 3~6분 | 튜토리얼 힌트 2 → ATK 강화 2회, 1-5 도달, 히어로 Lv 5 → 회전베기 해금 | 골드를 쓰는 곳이 여러 개다 |
| 6~12분 | 1-9까지 진행, 스킬 자동 발동 관찰, 튜토리얼 힌트 3 | 스킬은 알아서 쓰이고, 눌러서 당길 수도 있다 |
| 12~18분 | 1-10 보스 도전 → 실패 가능 → 후퇴 파밍 | 막히면 파밍하면 된다 |
| 18~30분 | 강화·가챠 반복 → 보스 재도전 성공 → 챕터 2 + 젬 50 | 벽은 넘을 수 있다 |

### Difficulty Curve

**난이도는 스테이지당 적 수가 아니라 적 능력치로 표현한다.** 일반 스테이지의 킬 목표는 g 전 구간에서 **8마리 고정**이고 보스 스테이지는 1마리다.

기존 구현의 킬 목표 공식(`5 + (ch−1)×10 + (stage−1)×2`)은 폐기한다. 그 공식은 후반에 63마리까지 늘어나 스테이지 1회가 4분을 넘겼고, 이는 필러 P2(25초 스테이지)와 정면 충돌한다.

| 구간 | g 범위 | 설계 의도 | 주된 돌파 수단 |
|---|---|---|---|
| 도입 | 1~9 (챕터 1 일반) | 저항 없는 우상향. 무조작으로도 계속 진행됨 | 자동 레벨업 |
| 첫 벽 | 10 (1-10 보스) | 보스 15배 HP를 처음 만난다. 1~2회 실패를 예상 | 강화 + 첫 가챠 |
| 학습 | 11~16 | 다시 순항하며 4슬롯 장비의 의미를 익힌다 | 가챠 |
| 의도적 정체 | 17~20 (2-7 ~ 2-10) | **첫 진짜 정체 구간.** 성장률 격차(1.10 vs 1.08)가 누적되어 파밍 없이는 못 넘는다 | 후퇴 파밍 + 강화 집중 |
| 확장 | 21~50 (챕터 3~5) | 정체-돌파 사이클이 챕터 단위로 반복. 스킬 레벨업이 새 변수로 들어온다 | 스킬 + 장비 상위 등급 |
| 무한 | 51+ | 챕터 테마를 순환 재사용하며 공식만 계속 적용 | 전부 |

**난이도 조정 레버는 3개뿐이다** — 적 HP 성장률, 스테이지 골드 성장률, 보스 배율. 스테이지별 수동 튜닝 테이블을 만들지 않는다. 1인 개발에서 50개 스테이지를 손으로 맞추면 유지가 불가능하고, 무한 확장과도 맞지 않는다.

**벽의 감지와 완화.** 같은 스테이지에서 3회 연속 실패하면 제안을 띄운다 — 보스 스테이지면 후퇴 파밍, 일반 스테이지면 한 단계 낮은 스테이지로의 파밍 이동이다. 그 외의 자동 난이도 완화(적 약화, 보상 증가)는 넣지 않는다 — 플레이어가 자기 선택으로 넘었다는 감각을 남기기 위함이다.

### Economy and Resources

**재화 2종.** 골드는 주 재화이고 젬은 확장 슬롯이다. MVP에 결제는 없지만, 나중에 IAP 상품을 얹어도 경제 구조를 다시 설계하지 않아도 되는 형태로 고정한다.

#### 골드 (Gold)

| 구분 | 항목 | 규모 |
|---|---|---|
| **소스** | 스테이지 클리어 | `50 × 1.04^(g−1)` — **주 수입**. 25초당 1회 |
| | 오프라인 축적 | 초당 `파밍스테이지_골드 / 3000`, 최대 6시간 — **보조 수입**(하루 합계 전체의 35~40%) |
| | 광고 오프라인 2배 | 오프라인 계산액 ×2, 1일 5회 |
| | 광고 골드 부스터 | 10분간 스테이지 골드 ×2, 1일 1회 (D-064) |
| | 중복 장비 환급 | 50 / 200 / 800 / 3,000 (최대 강화 레벨일 때만) |
| | 보스 격파 | 스테이지 골드 ×5 |
| | 젬 → 골드 패키지 | 젬 소비 |
| | 일일 던전 (D-100) | 골드 던전: 처치마다 스테이지 골드 × 0.5, 하루 2회 |
| **싱크** | 스탯 강화 6종 (D-142) | `baseCost × 1.12^level`. HP·ATK·DEF·치명 피해는 상한 없음, 공격속도 100·치명타 확률 25 — **주 싱크**. 10레벨마다 한계 돌파(돌파석) |
| | 장비 가챠 | 1회 500 / 10연 4,500 |

**인플레이션 통제 장치**

1. **지수 비용 vs 지수 수입.** 강화 비용 성장률 1.12가 스테이지 골드 성장률 1.08보다 크다. 골드는 늘어나지만 강화 1레벨의 가격이 더 빨리 오르므로 잔고가 무한히 쌓이지 않는다. HP·ATK·DEF에 상한을 두지 않는 것도 같은 이유다 — 상한이 있으면 골드가 갈 곳을 잃는다.
2. **소비처 3개 경쟁.** 강화·가챠·스킬이 같은 골드를 놓고 경쟁한다. 단일 소비처면 최적해가 자명해져 선택이 사라진다.
3. **오프라인 6시간 상한 + 낮은 효율.** 방치 수입에 절대 상한이 있고, 효율이 온라인의 약 6%라 방치만으로 진행이 끝나지 않는다.
4. **목표: 획득 골드의 90% 이상이 24시간 내 소비된다.** 시뮬레이션 검증 항목(→ 목표 곡선).

#### 돌파석 (D-143)

| 구분 | 항목 | 규모 |
|---|---|---|
| **소스** | 일일 던전 한 판 (골드·경험치, 1-10 이후) | 2개 × 하루 4판 |
| | 무한의 탑 층 | 1개, 10층마다 +5 |
| **싱크** | 능력치 한계 돌파 | k번째 돌파 10 × k개, 레인마다 따로 |

돌파석은 캐릭터 창 탭 줄 오른쪽에 개수가 보인다. 매일 던전과 탑을 도는 플레이어는 남고, 던전을 건너뛰면 능력치가 10레벨 단위에서 멈춰 던전·탑으로 유도된다.

#### 상점 · 소환권 (D-128, 장르 표준 일일 상점)

**소환권**은 장비·스킬·펫 소환 1회권이다(확률·천장·소환 단계·카운터는 유료 뽑기와 같다). 소환 화면 골드 패키지 자리에 `소환권 N회 (보유 M)` 버튼이 있어 보여 주는 소환의 소환권을 최대 10장씩 쓴다(스킬은 전직 후, 펫은 펫 소환 개방 후). 소환권은 상점과 무한의 탑에서 얻는다.

**상점**(오른쪽 메뉴, 무료 선물이 남으면 빨간 점):

| 상품 | 내용 | 가격 | 제한 |
|---|---|---|---|
| 매일 무료 선물 | 장비 소환권 ×5 | 무료 | 하루 1회 |
| 오늘의 특가 · 장비 | 장비 소환권 ×10 | 150젬 | 하루 1회 |
| 오늘의 특가 · 스킬 | 스킬 소환권 ×10 | 180젬 | 하루 1회 |
| 오늘의 특가 · 펫 | 펫 소환권 ×10 | 180젬 | 하루 1회 |
| 골드 상자 | 파밍 스테이지 골드 × 100 | 50젬 | 없음 |

특가는 젬 10연(200)보다 조금 싸지만 하루 1회라 젬 10연 버튼을 대체하지 않는다. 상시 싼 묶음은 두지 않는다(젬 10연이 쓸모없어진다). 일일 상품은 기기 로컬 자정에 초기화된다.

#### 광고 슬롯

| 슬롯 | 용도 | 보상 | 1일 제한 | 실패 처리 |
|---|---|---|---|---|
| A-1 | 오프라인 보상 2배 | 계산된 골드 ×2 | 5회 | 2배 버튼 비활성 + 토스트. 일반 수령은 항상 가능 |
| A-2 | 젬 획득 | 젬 5 | 5회 | 버튼 비활성 + 토스트. 재시도 가능 |

- 일일 제한은 기기 로컬 자정(00:00) 기준으로 리셋한다.
- 광고 시청 중 이탈하면 보상을 지급하지 않고 횟수도 차감하지 않는다.
- **광고 없이도 게임이 완주 가능하다.** 광고는 전부 가속 수단이며, 광고 전용 콘텐츠는 만들지 않는다.
- 2배속(A-6, 왼쪽 레일 세 번째 버튼)은 전투 로직·애니메이션·이펙트를 함께 빠르게 하고(게임 시간), 광고·오프라인 타이머는 실제 시간 그대로다. 하루 3회면 광고 시청자가 7일차에 2~3챕터 앞서 1회로 정했다.
- 무료 소환(A-4·A-5)은 유료 뽑기와 같은 확률표·천장·소환 레벨·카운터를 쓴다. 소환 화면의 골드 패키지 왼쪽 `광고 보고 무료 10회 (남은/하루)` 버튼(장비·펫 탭, 스킬 탭에는 없음).

**IAP 로드맵 (v1.1)** 광고 제거 + 오프라인 상한 12시간 패키지 / 젬 번들 / 첫 결제 보너스. 확률형 아이템 직접 판매는 계획하지 않는다.

#### 일일 콘텐츠

일일 퀘스트와 출석 보상은 **v1.1**이다. MVP에서 일일 리셋을 갖는 것은 광고 슬롯 3종의 횟수 제한뿐이다. 일일 콘텐츠를 v1.0에 넣지 않는 이유는 그것이 리텐션 장치이지 핵심 루프가 아니며, 1인 개발에서 핵심 루프의 완성도를 먼저 확보해야 하기 때문이다. (D-099·D-100에서 출석·일일 미션·던전을 v1.0에 넣었다.)

#### 로컬 알림 (D-119, 장르 표준 복귀 알림)

앱을 백그라운드로 보내거나 끌 때 기기 안에서 두 알림을 예약하고, 돌아오면 모두 지운다. 서버 푸시는 쓰지 않는다.

1. **오프라인 보상 가득:** 지금 + `OFFLINE_CAP`(6시간) — "오프라인 보상이 가득 찼어요! / 6시간 동안 모은 골드를 받으러 오세요"
2. **새 하루:** 다음 날 오전 9시 — "새로운 하루가 시작됐어요 / 출석 보상과 일일 미션, 던전이 기다려요"

- 설정 팝업의 `알림` 줄로 끈다(기본 켬, 저장 `notificationsOff`).
- Android 13+ 알림 권한은 첫 세션이 아니라 두 번째 실행부터(뽑기를 한 번이라도 한 저장) 한 번만 묻는다(`notifyAsked`).
- Unity Mobile Notifications 2.3.2, 채널 `solohero_default`. 버전 정의 `SOLOHERO_NOTIFICATIONS`로 감싸 패키지가 없거나 에디터면 아무것도 하지 않는다.

## Level Design Framework

### Level Types

"레벨"은 스테이지 단위이며 수작업 레이아웃이 없다. 배경 테마와 적 구성 조합으로 만들어진다.

| 타입 | 구성 | 킬 목표 | 제한 시간 | 출현 |
|---|---|---|---|---|
| **일반 스테이지** | 챕터 테마 적 2~3종 혼합 스폰 | 8 | 없음 | 챕터당 9개 (stage 1~9) |
| **보스 스테이지** | 챕터 전용 보스 1체 | 1 | 30초 | 챕터당 1개 (stage 10) |

**챕터 테마 10종 (D-131).** 11장부터는 1장부터 다시 돈다(능력치는 g를 따른다). 배경·바닥은 `bggen.py`·`floorgen.py`, 캐릭터는 `chibi3d.py`(Blender) 절차 생성.

| 장 | 테마 | 배경 | 적(근접·돌격·탱커·원거리) | 보스 |
|---|---|---|---|---|
| 1 | 초원 | 하늘·구름, 언덕, 둥근 나무 | 고블린·눈알·버섯·해골 | 떠돌이 검귀 |
| 2 | 설산 | 눈 덮인 봉우리, 침엽수 | 고블린·눈알·파란 버섯·해골 | 해골 주술사 |
| 3 | 숲 | 빛줄기, 큰 침엽수 | 붉은 고블린·눈알·버섯·해골 | 숲의 추적자(골렘) |
| 4 | 황혼 | 밤하늘·달, 보랏빛 능선 | 붉은 고블린·붉은 눈알·파란 버섯·보라 해골 | 그림자 마도사 |
| 5 | 노을 | 해, 분홍 언덕 | 붉은 고블린·붉은 눈알·버섯·보라 해골 | 화염 마법사 |
| 6 | 사막 | 해, 모래 언덕, 선인장 | 모래 고블린·눈알·버섯·해골 | 사막 도적왕 |
| 7 | 화산 | 붉은 하늘·불티, 용암 봉우리, 마른 나무 | 붉은 고블린·붉은 눈알·파란 버섯·붉은 해골 | 용암 골렘 |
| 8 | 늪 | 탁한 하늘·안개, 늪 덤불 | 고블린·눈알·초록 버섯·해골 | 늪지 마녀 |
| 9 | 수정 동굴 | 보랏빛 밤, 수정 첨탑 | 붉은 고블린·하늘색 눈알·파란 버섯·보라 해골 | 수정 골렘 |
| 10 | 마왕성 | 붉은 달, 검은 첨탑 | 붉은 고블린·붉은 눈알·파란 버섯·붉은 해골 | 마왕 기사 |

적은 같은 생물이 같은 역할을 맡고(D-110) 장마다 색 변형만 바뀐다. 음악은 1~5장 곡을 다시 쓴다. 이전 기록(MVP 초안 5테마·보스 3종, D-068·D-082·D-084의 에셋 교체)은 decision-log에 남아 있다.

### Level Progression

1. **구조:** 챕터 1개 = 10스테이지, 10번째가 보스. MVP는 챕터 5개 = 50스테이지.
2. **해금:** 챕터 N의 보스를 격파하면 챕터 N+1의 1스테이지가 열린다. 스테이지 단위 해금은 순차 진행뿐이다.
3. **최고 도달(highest) vs 현재 파밍(farming) 분리:** 최고 도달은 감소하지 않는 기록이고, 파밍 스테이지는 플레이어가 최고 도달 이하에서 자유롭게 지정한다. 앱을 다시 켜면 파밍 스테이지에서 시작한다.
4. **스테이지 선택 UI:** 상단 스테이지 바를 탭하면 선택 시트가 열린다. 잠긴 스테이지는 흐리게 표시하고 탭해도 반응하지 않는다.
5. **자동 진행:** 클리어 후 2초 뒤 다음 스테이지로 자동 진행한다. 단 플레이어가 파밍 스테이지를 수동 지정한 상태라면 그 스테이지를 계속 반복한다. D-125: 일반 → 일반(반복 파밍 포함)은 끊김 없이 이어진다 — 2초 동안 영웅이 앞으로 달려 배경·바닥이 흐르고, 다음 무리는 화면 오른쪽에서 걸어 들어온다(위치를 0으로 되돌리지 않는다). 보스 스테이지·새 챕터·사망 후 재시작은 처음 위치에서 시작한다.
6. **무한 확장:** 챕터 6 이상은 챕터 1~5의 테마를 순서대로 순환 재사용하고(챕터 6 = 초원 재사용), 수치는 g 공식이 계속 적용된다. 새 테마 추가는 v1.1 콘텐츠 업데이트로 한다.
7. **체크포인트 없음.** 스테이지 내부에는 저장 지점이 없다. 스테이지가 최소 단위다.

**왜 챕터당 100스테이지가 아닌 10인가.** 레퍼런스 게임은 챕터당 100스테이지를 쓴다. 10으로 줄이면 "챕터 클리어"라는 이벤트가 하루에 1~2회 발생하게 되어 1인 개발 규모에서도 진행 보상(젬·테마 전환)을 촘촘하게 줄 수 있다. 100스테이지 구조에서는 챕터 전환이 며칠에 한 번이라 중간 목표가 비어버린다.

## Art and Audio Direction

### Art Style

**픽셀아트, 세로 1080×1920.** 무료 에셋(itch.io / Unity Asset Store / Kenney 등)을 기반으로 하고, 확보되지 않은 항목은 플레이스홀더 색상 박스로 개발을 진행한다.

| 항목 | 기준 |
|---|---|
| 기준 해상도 | 1080×1920 (Portrait) |
| 픽셀 퍼펙트 기준 해상도 | **270×480** — 정수 4배 업스케일로 1080×1920을 채운다 |
| PPU (Pixels Per Unit) | **32** — 1 unit = 32 px. 상수표의 units 수치는 모두 이 기준이다 |
| 화면 크기 (unit 환산) | 8.44 × 15.0 units. 전투 뷰는 세로 8.25 units |
| 픽셀 단위 | 픽셀 퍼펙트 유지 — 스프라이트를 비정수 배율로 스케일하지 않는다 |
| 히어로 크기 | 32×32 px = 1×1 unit (기준 해상도 480 px 높이의 약 6.7%) |
| 일반 적 크기 | 24×32 px 기준 |
| 보스 크기 | 64×64 px 기준 (일반 적의 2배 실루엣) |
| 배경 레이어 | 챕터당 3레이어 패럴랙스 (원경 / 중경 / 근경) + 지면 타일 1 |
| 팔레트 | 챕터 테마별 8~12색 제한 팔레트. 등급 색상(회/청/보라/금)은 팔레트와 별개로 UI 전역 고정 |
| 캐릭터 명암 (D-150) | 3D 렌더 → 도트. 키 라이트는 왼쪽 위 옆에서 (-0.7, 0.55, 0.45), 재질마다 그림자·기본·하이라이트 3단(경계 0.45/0.88, 얼굴 0.28/0.9, 바위 0.1/0.55). 팔레트는 벌려 쓴다 — 그림자는 기본보다 확실히 어둡고 조금 차갑게, 하이라이트는 흰색 대신 기본색을 남기고 조금 따뜻하게(`tools/art/punch.py`). 외곽선 #2b1d3a + 셰이더 테두리(D-112) |
| 필수 애니메이션 클립 | Idle / Run / Attack / Hit / Die (+ 히어로는 Skill 1~3) |
| 프레임 수 권장 | Idle 4 / Run 6 / Attack 6 / Hit 2 / Die 6 |
| 히트 프레임 | Attack 클립의 3프레임 지점에 판정 이벤트를 둔다 |

**연출 우선순위.** 1인 개발에서 연출 예산은 유한하므로 아래 순서로 투자한다.

1. 피격 플래시 (적이 맞은 것이 보여야 전투가 살아난다)
2. 데미지 텍스트 (숫자가 성장의 증거다)
3. 골드 카운트업 (보상의 체감)
4. 가챠 카드 뒤집기 (뽑기의 기대감)
5. 강화 성공 펀치 (선택의 보상)
6. 카메라 셰이크 (보스·크리티컬·Epic 이상 획득)
7. 레벨업 링 이펙트

**스킬 연출 (D-146).** 스킬은 등급이 오를수록 화려해진다 — 장르 관습대로 등급이 곧 연출의 크기다.

| 층 | 일반 | 희귀 | 영웅 | 전설 | 직업 궁극기 |
|---|---|---|---|---|---|
| 발밑 마법진 | 은빛 고리 | 푸른 이중 고리·룬 | 보라 삼중 고리·육망성 | 금빛 별 마법진·가시 | 금빛 별 마법진 (크게) |
| 빛기둥 (캐릭터 뒤) | — | — | 보라 | 금빛 | 금빛 (크게) |
| 이름 | 영웅 머리 위 | ← | ← | 금빛 리본 | 컷인 띠 (어둡게·초상·속도선) |
| 클립 크기 / 광채 세기 | ×1 / 0.5 | ×1.08 / 0.6 | ×1.18 / 0.72 | ×1.3 / 0.86 | ×1.4 / 0.95 |
| 착탄 | 속성 입자 | ← | + 별빛 폭발 | ← | ← |
| 화면 번쩍임 (흰빛 위주) | — | — | 0.1 | 0.16 | 0.24 |

광역 스킬은 착탄점에 바닥 충격파를 남긴다. 입자의 색과 움직임은 스킬 클립과 색에서 판별한 속성 10종(불·얼음·번개·신성·암흑·비전·독·바람·자연·물리)을 따른다 — 불씨는 오르고, 얼음·번개 조각은 튀고, 눈은 내린다. 스킬 데이터에 연출 필드를 따로 두지 않으므로 새 스킬도 클립과 색만 정하면 같은 규칙을 탄다. 셰이크와 히트스톱도 등급과 함께 커지고, 시전한 스킬바 슬롯은 등급 색으로 번진다. 모든 빛(광채·기둥·별빛·입자)은 가산 혼합 한 재질이다.

**저사양 대응.** 이펙트 축소 옵션과 30fps 모드를 설정에 둔다. 이펙트 축소 시 파티클과 카메라 셰이크를 끄고 데미지 텍스트는 유지한다 — 정보는 줄이지 않는다. 스킬은 클립·이름·소리만 남긴다(마법진·빛기둥·광채·입자·컷인·화면 번쩍임 없음, D-146).

### Audio and Music

| 항목 | 방향 | 개수 |
|---|---|---|
| BGM | 칩튠 / 레트로 루프. 챕터 테마별 1곡 + 보스 1곡 | 6곡 |

- 무료 에셋 라이선스는 출시 전 일괄 확인이 필요하다. `[확인 필요]`

## Technical Specifications

이 절은 *무엇 위에서 돌아가는가*와 *측정 가능한 목표치*만 규정한다. 시스템을 어떻게 구성하는지는 아키텍처 문서의 몫이다.

### Performance Requirements

| 항목 | 목표 | 측정 방법 |
|---|---|---|
| 프레임레이트 | 중급 기기에서 60 FPS 지속 | 전투 10분 연속 측정, 하위 1% 프레임 기준 |
| 저사양 모드 | 30 FPS 안정 | 설정에서 수동 전환 |
| 드로우콜 | 전투 화면 120 이하 | 프로파일러 |
| 메모리 | 400 MB 이하 | 2시간 방치 후 측정 |
| 동시 화면 적 수 | 4마리 (스폰 상한) | — |
| 30분 방치 안정성 | FPS 저하 10% 이내, 메모리 증가 10% 이내 | 30분 프로토콜 |
| 2시간 방치 안정성 | 크래시 없음, 메모리 증가 20% 이내 | 2시간 프로토콜 |
| 앱 시작 → 전투 진입 | 8초 이내 (네트워크 정상) | 콜드 스타트 10회 평균 |
| 크래시 프리 세션 | 99.5% 이상 | 출시 후 콘솔 지표 |

**누수 통제 원칙.** 적, 데미지 텍스트, 이펙트, 투사체는 전부 재사용 풀에서 공급하며 런타임 중 새로 생성하지 않는다. 레퍼런스 게임의 최대 불만이 최적화였다는 점을 설계 제약으로 받아들인다.

**묶어 그리기 (D-149).** UI 이미지는 필터별 아틀라스 3장(UiHd·UiItems·UiPixel), 효과 시트는 Vfx 아틀라스 한 장에서 그린다. 새 이미지는 해당 폴더에 넣으면 다음 아트 빌드에서 아틀라스에 들어간다. URP 동적 배칭을 켜 같은 재질·텍스처의 스프라이트를 한 번에 그린다. 이미지마다 텍스처가 따로거나 배칭이 꺼져 있으면 요소 하나가 드로우콜 하나가 된다 — 10-08에 전투가 130~300이었던 이유다(지금 평소 47). 측정은 개발 빌드의 `[Perf]` 로그(10초 구간 최고 `windowPeak`)와 `DrawCallProbe`로 한다.

**저장 신뢰성 요구**

1. 원격 저장과 로컬 백업을 동시에 유지한다. 로드 시 리비전이 높은 쪽을 쓰고(D-073), 원격이 6초 안에 응답하지 않거나 실패하면 로컬 백업으로 시작한다(D-136: 네트워크 없이 켜면 로딩 화면에서 멈추던 결함). 첫 실행 익명 로그인도 10초 제한 후 로컬 모드.
2. 저장 트리거: 앱 일시정지·종료(항상) + 스테이지 클리어 / 가챠 결과 확정 / 장착 변경 / 강화 성공 / 스킬 레벨업 / 오프라인 보상 수령 직후.
3. 저장 요청은 250 ms 디바운스 큐를 거쳐 하나씩 처리되어야 한다. 같은 프레임에 여러 트리거가 겹쳐도 저장이 중복 실행되거나 유실되지 않는다.
4. **어떤 경우에도 데이터가 초기화된 것처럼 보이지 않아야 한다.** 로드 실패 시에도 최소 방어 UI로 상태를 설명한다.
5. 기존 v1 저장 스키마에서 v2로의 이관 경로를 제공한다. 기존 개발 데이터가 있는 계정도 진입 실패가 없어야 한다.
6. **계정 도구 (D-134, 설정 → 계정):** 계정 ID 표시·복사, 기기 이전 코드(12자, 24시간, 서버에 진행 사본을 두고 새 기기가 가져가며 지움), 모든 데이터 삭제(서버 진행·발급 코드·익명 계정·기기 데이터·분석 ID). 이전·삭제 중에는 게임의 저장을 멈춰 결과를 덮어쓰지 않는다. 둘 다 끝나면 앱을 다시 시작한다.

**Q-1 해소 내역.** 초안의 첫 상수 조합에서는 적 HP가 `1.10^g`로 지수 성장하는데 플레이어 공격력은 강화 레벨에 가산(레벨당 +5)되고 강화 비용이 지수여서, 강화 레벨이 g에 선형이고 따라서 공격력도 선형이었다. 지수 대 선형이므로 어떤 파밍 시간을 들여도 후반에 25초 목표가 붕괴했다. 세 가지 구조 변경안(강화 승산화 / 적 능력치 다항식화 / 프레스티지 v1.0 이동)을 검토해 **강화 승산화**를 선택했다 — 변경 범위가 가장 작고, 방치형에서 표준적인 구조이며, 프레스티지를 v1.2에 남겨둘 수 있다. 확정 내용은 다음과 같다.

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| HP·ATK·DEF 강화 효과 | 가산 (+50 / +5 / +5) | **승산 ×1.16 / 레벨** |
| 강화 최대 레벨 | 100 (전 레인) | **HP·ATK·DEF 상한 없음**, 공격속도만 100 |
| 강화 비용 성장률 | 1.15 | **1.12** — 파밍 효율 지수 `ln1.16/ln1.12 = 1.31` |
| 방어력 기본값 | 0 | **10** (승산 대상이라 0이 될 수 없다) |
| 방어력 적용 방식 | 감산 차감 | **자기 스케일링 비율 감쇄** (`DEF_REF = 8 × 적 공격력`) |
| 적 공격력 성장률 | 1.09 | **1.10** (HP와 동률 — 플레이어 HP도 승산이므로) |
| 보스 HP 배율 | 8배 | **15배** (30초 제한과 합쳐 일반 스테이지의 1.6배 DPS 요구) |
| 오프라인 제수 | 50 (온라인의 50%) | **400 (약 6%)** — 오프라인을 보조 수입으로 격하 |

**오프라인을 보조 수입으로 둔 근거.** 제수 50에서는 6시간 방치 한 번이 스테이지 1-10까지 온라인으로 번 누적 골드(약 724골드)의 약 30배를 주어, 진행·강화·가챠의 선택이 전부 무의미해졌다. 제수 400이면 6시간 방치가 온라인 약 22분 분량이 되어 "다시 켤 이유"로 기능하면서도 온라인 파밍을 대체하지 않는다. 이에 따라 USP 2의 문구를 "주 수입원"에서 "복귀 보너스"로 고쳤다.

**남은 검증.** 위 구조는 성장 차원을 맞춘 것이고, 목표 곡선의 1일·3일·7일 체크포인트가 실제로 달성되는지는 여전히 시뮬레이션으로 확인해야 한다(→ Q-2, V-1 ~ V-7).
