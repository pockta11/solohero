## 이번에 찾아서 고친 문제

1. **[Critical] 강제 종료 직후 원격 저장이 로컬을 덮어써 진행이 사라질 수 있음** — 로드 시 원격(Firebase)을 무조건 우선했고, 저장은 250 ms 디바운스 후 로컬·원격을 함께 썼다. 구매 직후 앱이 죽으면 (a) 로컬도 안 써졌거나 (b) 원격 업로드 전이라 다음 실행에서 옛 원격본이 이겼다.
   - 수정: `SaveDataV2.saveRevision`(저장 요청마다 +1), 로드 시 로컬·원격 중 **리비전이 높은 쪽** 사용(로컬이 새로우면 원격에 업로드), 저장 요청 즉시 로컬 기록(원격만 디바운스). 테스트 3개 추가.
2. **[Critical] 빌드에서 Firebase 네이티브 라이브러리 누락 → 로컬 모드로만 부팅** — EDM4U가 `firebase-app-unity` pom을 `srcaar`로 바꿔 Gradle이 aar을 못 찾음. 빌드 전 자동 복구 + 빌드 후 `libFirebaseCppApp` 포함 검사(없으면 빌드 실패).
3. **[Major] 보스 실패 팝업이 입력을 기다리며 방치 진행이 멈춤** — 2시간 방치 1차에서 1-10 보스 실패 후 13분 넘게 진행 0. 방치형은 아무도 안 볼 때도 파밍이 계속돼야 한다. 수정: 5초 카운트다운 후 자동 후퇴(D-077, `BOSS_FAIL_AUTO_RETREAT`). 방치 2차로 재검증.

## 알려진 문제

1. **에뮬레이터에서 광고 WebView가 약 85초 후 앱을 종료시킴** — 광고 켠 x86_64 네이티브 빌드는 244초 무크래시 → arm64 번역 실행 한정으로 추정. — `libmonochrome_64.so`(Chrome WebView) `MemoryInfra` 스레드 SIGTRAP. 스택에 게임 코드 없음. 광고 SDK를 끈 QA 빌드는 5분 이상 정상. x86_64 호스트에서 arm64 앱을 번역 실행하는 16 KB 페이지 이미지의 문제로 추정 — **실기기 확인 필요 (E9-12)**. 확인 전까지 출시 게이트 항목.
2. 에뮬레이터는 SwiftShader 렌더링이라 FPS·드로우콜 수치는 기기 성능을 대표하지 않는다 → E9-12·E9-19는 실기기에서.
3. 스모크의 "신규 진입"은 앱 데이터를 지워 매번 새 익명 계정을 만든다 — Firebase Auth에 테스트 계정이 남는다(무해, 콘솔에서 정리 가능).
4. 크래시 프리 세션(GDD 목표 99.5%)은 Crashlytics 없이 Play Console **Android vitals**로 본다 — 새 네이티브 SDK를 넣지 않아 16 KB 재검증이 필요 없다.

1. B-001(에뮬레이터 번역 실행 시 광고 WebView 종료) — 그대로. 실기기 확인 필요.
